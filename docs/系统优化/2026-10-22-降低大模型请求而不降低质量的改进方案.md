## 结论

本次复核没有发现已经能够证明“当前优化降低了内容质量”的缺陷。3.8.0—3.8.2 已上线的连接复用、Codex 启动节流、事件综述防抖、预筛持久化批量和单请求合并，均保留了两次独立评分、回执身份、消费者登记、unknown 等待与恢复边界。

## 当前请求路径

| 路径 | 当前行为 | 判断 |
| --- | --- | --- |
| 预筛 | 5 篇或 30 分钟持久化批量，按成员逐篇校验 | 已是低风险的主要请求削减；不应改成标题或 RSS 摘要先筛 |
| 评分 | 每篇两次独立评分，合计决定精选 | 是当前质量保护边界；不能直接合并为一次回答 |
| 写作与结构 | 模型配置兼容时合并为一次，否则分别请求 | 已避免一部分重复输入，继续保留 |
| 事件归组 | 候选一次批量判断；相似度低于 0.85 时才追加复核 | 已有批量和相似度短路，不建议盲目扩大候选数 |
| 事件综述 | 固定约 5 分钟防抖；单报道可直接复用公开文字 | 已有主要防抖，仍可处理完全重复报道 |
| 正文翻译 | 每约 3500 字符一批；错位时拆分重试 | 正常路径合理，异常路径可能产生额外请求 |

`paidRequest` 的逻辑身份已经按服务、用途、模型、系统输入、用户输入和轮次复用，且逻辑键不包含文章 subject。因此，完全相同的请求已有跨文章复用能力，不需要再建立一个内容不受约束的全局缓存。

## 已确认的改进点

### 1. 分析复用使用了过宽的材料哈希

`packages/backend/src/editorial/analyze.ts` 的 `savedStep()`、结构、理解、摘要和合并路径都使用 `materialHash(a)` 判断已保存结果是否可以消费。该哈希排除文章 ID 和 revision，但仍包含处理轮次、发现时间、媒体对象及其它不一定进入模型提示词的字段。

因此，只影响数据库记录或非模型输入的变化可能使 `savedStep()` 返回空值；但随后相同请求仍可通过底层逻辑键命中旧回执。初稿把这个回退直接推断成重新付费，证据不足，现已修正。当前确认的是上层消费条件较宽，可能增加配置／连接准备开销；是否增加真实 attempts，必须关联观察日志与 `receipt_attempts` 判断。

改进方式是为每个步骤保存**实际发送输入的哈希**：

- 预筛、评分继续按实际 user 输入复用；
- 结构按 `system + buildMaterial(a)` 复用；
- 理解按文本及图片部分的完整序列化输入复用；
- 摘要按最终摘要 user 输入复用；
- 合并路径按最终合并 system、user 和图片输入复用。

提示词版本、模型配置、reasoning effort、轮次标签、回执互斥和 unknown 保护保持不变。新增字段时保留旧 `materialHash` 的兼容读取，不能让旧回执因为代码升级而重新付费。

该候选只有在模型实际看到的输入完全一致时才能复用结果；在 P1 证实有实际收益前，不更改恢复身份。若后续实施，应覆盖以下回归：

1. 只修改发现时间、处理状态或未进入提示词的元数据，实际 attempts 不增加；
2. 修改标题、正文、来源分级、URL、引用或图片输入，必须产生新的请求；
3. 显式管理员重评使用新轮次，不能误复用旧轮次；
4. 旧提示词版本、pending、unknown 和部分完成回执继续沿原身份恢复。

### 2. 完全重复报道仍可能触发综述重写

`composeStoryDigest()` 已有输入哈希和 5 分钟防抖，但只要事件输入集合发生变化，就可能重新请求模型。若新加入的报道与已有报道的规范化标题、摘要和事实框完全相同，综述正文并没有新的事实信息，却仍会产生一次请求。

可以增加一个严格的确定性短路：只有在没有人工修正，且新增报道与已有报道的标题、摘要、事实框逐项相同的情况下，复制上一版综述并登记新的覆盖文章和审计版本。不能使用模糊语义相似判断代替模型，也不能因此跳过真正的新来源、新条件或矛盾信息。

### 3. 翻译错位路径需要先量化再优化

翻译批次正常时请求数可预测；发生数组长度或占位符错位时，当前路径会先保留原批次结果，再拆成左右两批重试。这个安全边界正确，但某些材料可能因此产生额外请求。

先按模型、来源类型、段落数量和字符数记录错位率及拆分后的成功率。只有在确认某类输入稳定错位后，才针对该类输入调整段落边界或提示格式。不能直接提高全局批次大小，否则可能以更少请求换来更多错位和不完整译文。

## 可尝试但必须先做 shadow 验证的方案

### 低分中文来源摘要直出

普通文章目前通常仍经过摘要模型。可以只对明显低于精选和理解门槛的文章尝试无模型路径，但必须同时满足：来源明确提供可用摘要、标题和摘要为中文、摘要长度在安全范围内、无图片事实和复杂引用、文章不是精选或接近精选。

该方案可能节省一部分摘要请求，但会改变公开摘要的编辑风格，不能直接视为无损优化。应使用历史材料做 shadow 对照，至少检查标题完整性、条件保留、主体身份、日期和事实归属，并要求人工抽查结果不劣于现有摘要路径。精选及接近精选文章不得使用该路径。

## 暂不建议的方向

- 将两次独立评分合并为一次回答；这会破坏当前评分独立性。
- 用标题或 RSS 摘要提前替代全文预筛；这会增加误拦和漏读风险。
- 删除结构请求；结构仍被事件归组和公开分类使用。
- 继续只压缩批次 JSON 表示；已有回放显示系统提示词计入字节仅下降 0.32%。
- 直接切换 10／60。以 10 篇常规文章估算，5／30 约 32 次请求，10／60 约 31 次，整体只减少约 3.1%，却可能增加等待。
- 降低当前理解、摘要、结构的强度，或通过提高并发来掩盖请求量问题。

## P1 实施：请求观察与只读日报

### 记录边界

- `operations/request-observation.ts` 输出带 schema、唯一 ID、UTC 时间的 JSON 行，仅记录用途、模型键、subject／revision、回执编号、计数和有限错误类别。白名单剥离正文、响应、URL、连接和授权对象；记录失败不改变原业务返回／异常。
- `chatJson()` 记录成功消费、复用与失败分类；`reuseJsonReceipt()` 记录本地命中、哈希失配、旧版本不兼容及 pending／unknown 等待。两次评分、轮次标签、消费者登记和互斥逻辑保持原样。合并路径原本先离线消费且没有构建实际 user，故该路径的 `userHashEqual` 为未知，不额外下载图片或连接模型来补统计。
- `digest-observation.ts` 只读观察新增报道：分别统计规范化标题摘要重复，以及同来源 ID、名称、一手标记、时间和事实框均一致的严格候选。缺少事实框、有人工修正、旧输入未获验证或强制重写时不计可短路候选。**候选计数不等于已证明可以省一次请求**；本轮仍走原综述生成和提交校验。
- 翻译记录来源类型、模型、段落数／字符数、初次／拆分／重试阶段、数组错位、拆分后的对齐结果、占位符错误与最终 translated／partial／failed／waiting／stale。拆分“对齐”仅指数组和非空字符串检查，完整译文仍以最终结果为准。原 3500 字符边界、重试及完整性判断保持不变。
- 无数据库迁移，不向业务表添加统计行；日志随服务标准输出持久化。日志不可用、被轮转或进程中断可能漏记，必须保留覆盖范围说明。

### 日报使用

通过外部环境提供目标 `DATABASE_URL`，脚本自身不加载 `.env`。以下为通用示例；本轮生产只读运行的实际时间和覆盖边界见发布记录：

```bash
node scripts/report-model-requests.ts --day 2026-10-22 \
  --log work/request-observation/worker.jsonl \
  --log work/request-observation/api.jsonl \
  --observation-start 2026-10-22T00:00:00+08:00
```

日志文件只应包含 `marker=model_request_observation` 的脱敏行；支持原始 JSON 行及 Docker `--timestamps` 的时间戳前缀，轮转文件重复行按事件 UUID 去重。不要把完整未筛选生产日志带出服务。`--observation-start` 必须填实际启用时间，不得照抄示例伪造完整日。

脚本在 `REPEATABLE READ READ ONLY` 事务中读取同一快照，输出：

| 字段 | 口径 |
| --- | --- |
| `consumption.attempts` | 当日北京时间 `[00:00, 次日00:00)` 内启动的 live 模型 attempts；包括失败、pending、unknown，按 attempt 主键全局计一次 |
| `consumption.groups` | 按 purpose、实际模型、attempt 状态、是否同回执重试及失败类别分组；不输出原始错误文本 |
| `knownTotalTokens`／`unknownUsage` | 完整用量记录的输入＋输出小计，以及缺失／异常用量条数；未知不补零、不核算费用 |
| `consumption.articles` | 按消费者映射至文章 revision 的关联 attempts／用量，翻译 `#段落` 合并到 revision；共享回执单列 `sharedAttempts`，逐篇数值不能相加当全局用量 |
| `throughput` | 当日到达文章数、非 stale 模型分析的去重完成 revision 数；另列查询时待处理和失败文章数，跨日积压不混进到达量 |
| `articles` | 当日到达、完成或消耗请求的文章集合，列查询时处理状态、公开投影 revision、可见性、精选、放行时间及统一公开谓词判断的 `currently_listed` |
| `observations` | 日志记录按事件、用途、模型、来源类型、阶段、段落／字符数量区间和结果分组；保留脱敏明细供 article revision 复核 |

成功消费复用率只统计 `chatJson` 成功和 `reuseJsonReceipt` 命中，不把失败或上层 mismatch 加入成功分母；不把持久化批次的逐篇结果读取当作额外模型调用。`materialMismatchSameUser` 仅表示上层材料失配而 user 哈希相同，**不表示新增付费**，且还须保留系统提示词、配置和轮次的区别。

批量预筛用一个回执统计真实请求，通过消费者映射关联多篇文章。错误类别为有界诊断分类，无法明确分类时保留 `other_failure`，不根据错误文案猜测账号原因。日报只统计具有模型提示词身份的 `chatJson` 回执，不包含正文抓取、向量或其它付费服务。

未提供日志时，数据库用量仍可读取，但 `observations.provided=false`、复用率为 null，不能解读为零复用。`eligibleFullDay` 只核对声明的启用时间、日期已结束及是否提供日志；仍须另核对日志完整性、轮转和停机。公开状态、消费者和 attempt 结果都是**查询时快照**，不追溯伪造历史日终状态。
