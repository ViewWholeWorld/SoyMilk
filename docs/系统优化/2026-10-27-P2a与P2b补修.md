## 实现边界

P2a 在解析合法 JSON 后，只恢复两个生产已见形状：完整 `writing.structure` 提升为同级对象；完整平铺字段重新分成两个对象。要求顶层仅有 `writing`，原字段完整且通过 schema；平铺 tags 必须已符合共同词表，原数组复用，不增加、推导或补写任何值。已有同级结构又含错位结构、字段不足、额外顶层／写作／结构字段、错误类型和非法分类不猜测合并，仍拒绝整份结果。已有有限语法修复与正文 JSON 字面文本边界继续保留。

P2b 普通文章、长帖与短帖输入分别指定合并 JSON 中的对应字段，不再嵌入 `title_zh:` 等旧文本输出行；单项路径保留原格式。共享规则增加具体券额、积分消耗与资格约束，区分本次获得积分与兑换所需积分，也区分现金实付和非现金返卡。

`writing.ts` 本地防护针对明确数字做有界检查：正文中仅有一种券额，文案报券后金额却未保留券额；或仅有一个积分兑换门槛，文案报兑换／折合金额却未保留该门槛。命中后相应标题／摘要清空，分析按既有规则为 UNKNOWN、非精选，不进入公开内容，并在 `analyses.output.priceEvidenceGuard` 记录字段、条件类型及数值。原始回执与模型响应保留，不为“修好摘要”新增请求，也不把原稿改写成看似已验证的文字。

该防护不是完整的价格语义验证器：多档优惠无法确定对应关系时不自动裁决；未覆盖所有表达、币种、资格、时间、补贴与跨句关系。普通实付、无价格的促销描述和完整条件文案保持。真材料不足的空摘要仍待确认，可能减少可发布内容，不能宣称生成质量已经全面改善。

修改提示词后加入本次生产版本的明确兼容白名单，仍检查材料指纹和完整 schema。已收到的旧结果可在配置变化后本地消费并执行当前防护，分析记录继续保留实际生成版本；pending／unknown 等待、失败有限恢复、两次评分、消费者与分步互斥保持。无迁移，未改变模型、账号、effort、预算、并发或生产开关。

额外复查发现：旧解析失败会把回执标为 failed，原 `storedReceipt()` 不再读取该输出，单改解析器仍可能重发。候选仅在 P2a 显式允许重读此类结果：回执因 `unusable output:` 失败、没有供应商拒绝、当前最新 attempt 为 received 且原响应存在。只读出原响应，通过版本、材料与完整 schema 后才在业务提交时完成原回执。解析仍失败则保持既有有限恢复；供应商拒绝、旧 attempt 遗留响应、pending／unknown 都不能通过此入口消费。不扫描或批量重开生产终态。
