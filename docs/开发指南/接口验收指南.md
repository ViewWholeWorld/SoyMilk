# 空库 HTTP API 验收

`npm run test:http` 是仓库长期维护的空库验收入口，与默认后端函数／数据库回归分开运行。它创建真实监听端口的 Fastify API，启动生产构建的 Web，所有用例均通过 Web 的 HTTP 代理发送请求；不使用 `app.inject()` 或网页测试中的假 API 替代实际调用。完整命令和历史结果见[隔离回归测试](隔离回归测试.md)。

## 运行方式

需要 Node.js 24、已安装的项目开发依赖、PostgreSQL，以及已完成的网页生产构建。在独立测试网络或仅启用 loopback 的网络命名空间内运行，禁止与生产服务共用网络或数据卷。

```sh
npm run build -w @aihot/web
# 在隔离 PostgreSQL 实例上另建数据库；不预先执行 migrate.ts。
createdb -h 127.0.0.1 -p 5432 soymilk_http_test
DATABASE_URL=postgres://127.0.0.1:5432/soymilk_http_test npm run test:http
```

连接串必须显式提供主机，数据库名以 `_test` 或 `_ci` 结尾；不接受 URL 查询参数或片段，防止驱动参数覆盖已验证的数据库名。入口连接前先校验连接串，然后检查数据库确实没有用户表、视图、函数或额外 schema；非空库直接失败。脚本不会 drop、truncate 或重置数据库。再次运行请另建空库；测试数据保留在专用测试库供排查，由维护者确认对象后自行删除。

脚本不加载 `.env`，通过白名单构造子进程环境，使用虚构管理员密码、会话密钥与 ingest token，建立独立空凭据目录和数据目录，关闭采集和模型环境开关。应用迁移与 pg-boss schema 初始化均在测试库执行；初始化队列用于验收后台任务页和排队命令，不启动 worker 的任务处理器，因此不会消费采集或模型任务。正式 worker 启动和 Docker／NAS 部署不属于此脚本的验证范围。

API、Web、本地 RSS 与图片替身均只监听 loopback、使用自动分配端口。入口检查生产构建文件存在；修改网页后仍须先重新构建，脚本不负责判断旧构建是否匹配当前源码。用例结束或正常收到 SIGINT／SIGTERM 时关闭服务并删除临时数据及凭据目录；日志与覆盖报告保留在 `work/http-acceptance-*/`，该目录不提交。报告与日志共同用于判断结果，强制终止进程无法保证留下完整报告。

## 覆盖与报告

入口执行 `tests/http/acceptance.test.ts`，复用 `scripts/smoke.ts` 的 29 项页面／机器出口冒烟及 `scripts/mcp-check.ts` 的五工具协议检查。它们不混算为 HTTP API 业务测试数量。

`tests/http/routes.ts` 登记显式 API 方法，与 Fastify `onRoute` 的实际注册结果双向核对。新增、删除或变更方法必须同步清单；登记后未实际调用同样失败。GET 自动生成的 HEAD 另作空响应体检查，不重复计作显式业务方法；OPTIONS、405 与通配符兜底单列为协议场景。静态资源、RSS、分享图及网页由冒烟和相关业务用例核验，不包含在 `/api/` 路由总数内。

`coverage.json` 按实际命中的方法和路由模板记录请求、状态、场景及层次：

报告的请求数只统计用例入口中带状态断言的调用，包含单列的 HEAD；冒烟脚本、MCP 客户端和 SSR loader 内部请求不混入该计数。

| 层次 | 含义 |
| --- | --- |
| `guard` | 匿名 401、缺失 CSRF 403、MCP Origin 等访问限制 |
| `empty` | 已迁移但无业务数据时的实际读取 |
| `boundary` | 非法参数、缺失记录、版本冲突、重复命令等边界 |
| `business` | 正常业务请求与响应字段、数据库结果或后续读取的断言 |
| `protocol` | HEAD、ETag／304、CORS、方法限制、MCP 协议 |

鉴权成功不代表业务覆盖。除协议兜底与明确登记的外部依赖例外，路由必须实际执行 `business` 场景才能通过覆盖门禁；只新增一条匿名 401 用例不能满足要求。该门禁检查路由和场景，不能替代人工审阅断言质量，也不表示分支覆盖率为 100%。

业务夹具包括：供应商去重及连接生命周期；调用聚合、过滤、分页、未知／零／部分用量、北京时间边界与每日趋势；退役价格／费用入口不再读取；本地 RSS 预览、信源编辑与采集排队；ingest 鉴权、批量校验、幂等和暂停；文章、主题、事件、热榜与三类刊物；人工修正、撤回、事件合并及重跑排队；下线入口 404 与退役采集拒绝；预算、回执核对、失败重排及评测导入。排队成功与工作任务执行成功分别验证，当前 HTTP 脚本不执行队列任务。

Codex 真实设备授权、账号状态、模型目录／退出需要外部账号或服务，列在 `businessGaps` 中；脚本验证其访问限制、输入拒绝或缺失会话，不执行真实授权。报告必须保留这些例外，不能将其写成成功业务已全覆盖。现有后端的本地协议替身回归继续保留，既有实现不因本任务更换接入方式。

## 新增或变更 API 的要求

1. 同步路由清单和真实 HTTP 用例，验证状态码、响应结构及关键业务值。按接口涉及的行为覆盖正常请求、空结果、缺失资源、非法参数、鉴权／CSRF、分页／筛选、版本冲突和幂等，避免只断言 200。
2. 需要数据时优先使用 `fixtures.ts` 的合成文章、回执和用量、虚构连接、生成的图片及本地 RSS。测试不得按当前生产配置猜测历史归属，不得加载生产授权文件。
3. 外部依赖使用受控本地替身，其余外部连接禁止。本地替身短暂放行内存中的私网访问配置，结束后恢复；环境安全阀始终关闭。旧 models.dev 片段仅保留为历史审计资料，价格目录同步已移除。
4. 如确需补充真实样本，只采集获准公开访问的内容或用户明确提供的日志。先脱敏并清除密钥、Cookie、个人信息及私网地址，记录来源、采集日期和用途，再冻结入库；回归时只读夹具，不联网爬取。不读取或提交生产数据库、`.env` 或 Codex `auth.json`。
5. 在新空库实际运行 `npm run test:http`，同时完成受影响的后端／网页回归。保留首次失败与修正后结果，在交付及 PR 中分别报告用例数、实际路由数、业务／协议覆盖和外部依赖例外；无法验证的行为明确列出。

网络隔离由运行环境提供，脚本的白名单环境与替身不是操作系统级防火墙。NAS 沿用独立 `--internal` 测试网络；不要为运行该套件改正式 Compose 或生产开关。
