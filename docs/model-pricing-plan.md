## 1. 目标与范围

在 `/admin/models` 为各供应商连接的不同模型配置价格，默认使用 models.dev 提供的官方参考价，允许管理员逐模型调整，并根据实际请求返回的 token 用量统计估算金额。

第一版包括：

- 以供应商连接和请求模型为维度管理价格；同名模型在不同连接下独立定价。
- 输入、输出、缓存读取和缓存写入四类单价，单位统一为每百万 token。
- models.dev 参考价目录、明确的模型映射、手动同步及恢复参考价。
- 每次真实请求保存连接归属、价格快照和估算结果，调价不改变历史金额。
- 按时间、连接、模型和用途汇总费用，并展示未定价、缺少用量与近似计价的覆盖情况。
- Codex 订阅用量按 API 参考价折算，单独展示，不算作订阅实际扣费。
- 历史记录的只读补算预览与可选、幂等的批量补算。

第一版不做汇率自动转换、订阅月费摊销、账单对账、按金额熔断、自动切换供应商、模型排行榜或公开费用接口。现有按请求次数的预算与回执保护继续使用。

## 3. 基本设计决定

### 3.1 供应商连接作为第一版定价边界

当前一个连接只有一个配置中的模型。第一版复用连接 UUID，使用 `(provider_key, requested_model)` 管理价格，不先重构成“一个 provider 管理多组连接”。一个连接先后使用过多个模型时保留其多条价格记录；同一个供应商的多组连接也独立配置。

- 后台连接：`connection:<uuid>`。
- 环境变量默认模型：`environment:default`，不能将 default 别名当稳定供应商；默认指向后台连接时必须解析为实际连接 UUID。
- 现有内置预设：`preset:<service>`，同一供应商的推理变体共用请求模型价格。
- 直接 Codex 入口：`subscription:codex`；高级 ChatGPT 授权入口单独使用 `subscription:chatgpt`。

解析归属使用请求开始时的实际 ModelSpec 和认证路径，不在统计时通过当前配置猜测。ModelSpec 可增加 connectionId 和计费类型，原预算 service 保持不变。

连接改名不改变价格与历史归属；删除连接保留历史快照及价格记录并标为已删除；切换模型只改变之后请求的价格查找。修改接口或密钥时沿用现有 generation 规则，同时提示管理员核对定价；同一 UUID 的费用仍属于该连接，快照记录当时名称。未来确需合并多连接供应商时另做显式分组，不按名称或 URL 自动合并。

### 3.2 价格与请求身份独立

价格、目录版本、映射和币种都不能进入 logicalKeyFor 的 identity，也不能触发连接 generation 更新。调价不能绕过旧回执、未知结果保护或订阅限流。

新增 billingContext 作为 ReceiptRequest 的独立可选元数据。原 requestSummary 仍为脱敏诊断摘要；不保存 API Key、授权令牌、账号邮箱或带凭据的 URL。非 LLM 服务不要求提供新字段。

### 3.3 费用分开存储和展示

保留 attempt 的 `cost/currency/cost_basis` 原语义，新增估算金额和价格快照；实际金额不能被本地估算覆盖。

展示至少区分以下三类：

1. 供应商返回的实际费用。
2. API 调用的本地估算费用。
3. Codex／ChatGPT 订阅用量的 API 等价金额。

第三类不加入 API 支出汇总。第二类只能称“估算费用”，第三方供应商没有提供实际账单时不能称“实际支出”。有实际金额的 API attempt 可保留估算值供检查，但综合费用中只取实际值一次。

第一版支持 USD、CNY；目录显式 currency 按供应商／模型／cost 声明读取，多处声明必须一致，RMB 规范为 CNY。无声明时仅依据固定 models.dev 源的 USD／每百万 token 约定回退，不按供应商地区猜币种；声明无效或冲突拒绝同步并保留旧目录。参考规则保存／恢复沿用目录币种，请求保留历史快照。跨币种分别汇总，不直接相加，不自动换汇；页面换算与汇率快照以后另做。

## 4. 数据结构建议

具体列名可在阶段 1 调整，但下面的信息与约束必须保留。

### 4.1 参考价目录

新增 `model_price_catalog`，唯一键 `(source, source_provider_id, source_model_id)`，保留：

- source 固定 models.dev，源 provider ID、model ID、名称与原币种。
- input/output/cache_read/cache_write 的每百万 token 单价；未知值为 null，零价为 0。
- 来源页 URL、成功拉取时间、目录修订标识、价格结构的内容 hash。
- supported 状态及不支持原因，例如阶梯计价、缺少币种或无法表达的缓存写入时长。
- 必要的原始价格片段，限大小，不保存整个未知 JSON 到前端契约。

同步后的目录是当前参考价。历史版本由请求快照保存，不要求第一版建立完整目录版本库。已被映射但从新目录消失的条目标为失效，保留最后成功值和时间，不删除关联。

### 4.2 模型定价规则

新增 `model_pricing`，唯一键 `(provider_key, requested_model)`：

- billing_kind：api 或 subscription_equivalent。
- mode：reference 或 custom。
- reference_provider_id、reference_model_id，可空；custom 模式也可保留映射用于对比。
- custom 模式的 currency、input/output/cache_read/cache_write 单价，reference 模式不存人工单价。
- revision、updated_at、updated_by、note；revision 用于乐观并发，避免多个管理员相互覆盖。

第一版选择整套价格覆盖：custom 至少填写输入和输出；缓存项允许未知。界面可先复制参考价再编辑，但保存后整套成为 custom。这样不会出现“缓存价跟着同步变、输入价保持旧值”的隐式混用。恢复参考价将 mode 改回 reference，保留明确映射，产生审计记录。

reference 的有效价格由本地目录解析；custom 由配置解析；没有新规则时可读取 service_prices 作为 legacy 回退，但必须有明确无歧义的 provider/service 对应，标注来源，并且只用于新调用快照。不能跨连接按模型名回退。不要双写两个价格表。

价格须为有限、非负十进制数，有明确最大值与小数位约束。建议单价 numeric(20,8)、金额 numeric(24,12)；实现前确认支持的最大用量与金额范围。计算用十进制定点或可靠的 decimal 实现，API 以十进制字符串传金额，展示时才舍入。服务端拒绝 NaN、Infinity、负数和超范围值，不通过 Number 的隐式转换将空白变成零。

### 4.3 attempt 快照与计算结果

对 receipt_attempts 追加可空字段：

- provider_key、provider_label_snapshot、billing_kind、requested_model、reported_model。
- pricing_snapshot JSONB：规则 revision、参考目录 hash、映射、币种、四类单价、来源时间、使用的缓存写入语义、calculator_version。
- normalized_usage JSONB：输入、输出、缓存读取、缓存写入、推理及缓存明细覆盖状态。
- estimated_cost、estimated_currency、estimate_status、estimate_detail。

estimate_status 建议为 complete、approximate、partial、unpriced、missing_usage、invalid_usage；detail 用结构化原因描述。partial 只代表部分可计价金额，不能混为完整费用。价格快照未配置时也要记录未定价原因，避免事后自动套新价。

在 paidRequest 的 claim/startAttempt 事务中解析本地价格并保存快照；无需外网。该事务采用一致的读取视图或一次原子查价，确保快照不是两版规则的混合。新重试使用新 attempt 当时的价格；复用已有回执不生成快照或费用记录。

拿到响应后，基于已保存快照计算，并与 response、usage 的回执保存一起提交。预计无法计价属于可记录状态，不抛出付费失败，不促使模型重发。数据库写入失败仍遵守原回执未知结果保护。计价模块不得改变原模型响应与业务处理语义。

对 `(provider_key, started_at)` 和需要的统计维度增量建索引，结合实际查询 EXPLAIN 决定，不预先堆叠索引。历史大表索引及迁移锁耗时需在隔离副本验证。

## 5. 用量归一化与计算规则

### 5.1 统一语义

归一化模块必须区分协议，不用一串 coalesce 把所有字段当同一语义：

- OpenAI 兼容 prompt_tokens 通常为总输入，cached_tokens 是其中子集。
- Codex 的输入、缓存与推理使用现有适配器输出核实；推理 token 已包含在输出时只用于展示，不再次计费。
- 某些协议 input_tokens 不含缓存读写，应先由对应适配器合成总输入。
- prompt_cache_hit_tokens / prompt_cache_miss_tokens 需要核对各供应商语义，不能凭名称猜测。

保存原始 usage，同时输出统一 `inputTotal/outputTotal/cacheRead/cacheWrite`；缓存读写应为输入总量中互斥的子集。第一版只为已验证协议添加适配器，其他协议标记缺少明细或不支持。

### 5.2 明细完整时

设总输入 I、总输出 O、缓存读取 R、缓存写入 W、对应单价 Pi/Po/Pr/Pw，普通输入 U = I - R - W：

```text
费用 = (U × Pi + R × Pr + W × Pw + O × Po) / 1,000,000
```

缓存写入价必须定义为完整单价。若来源给的是在普通输入价上的附加费，适配器先转换为完整价格并记录语义。若写入已经按普通输入收费且不存在额外收费，则保留普通输入价格，不能再重复加一笔。5 分钟／1 小时缓存价等多档写入无法由第一版单一字段表达时，标为不支持，允许人工明确选定适用价格并备注。

数值例：I=1,000,000、R=800,000、W=0、O=100,000；Pi=2、Pr=0.5、Po=8，则普通输入 200,000，费用为 0.4 + 0.4 + 0.8 = 1.6 USD。输出内含推理 token 时仍为 1.6 USD。

### 5.3 未知、不完整与异常

- 没有缓存明细，但有完整输入输出：按全部输入普通价估算，status=approximate；提示“缓存未知，按普通输入价估算”。不能称未命中，也不能保证这是上限。
- 已知有缓存读取但没有读取价格：可以按普通输入价近似计入该部分，明确记录降级原因；缺少缓存写入价且写入量已知时同理。若协议存在无法归一化的额外收费，标为 partial 或 unpriced，不能给出貌似完整的数值。
- 有普通输入或输出用量但缺少对应单价：保留可计算分项为 partial，完整费用为 null；缺失单价不能当 0。
- 缺少输入或输出计数：除非协议明确说明为零，否则 missing_usage 或 partial。返回总 token 数不能直接拆分。
- token 为负、非整数、超范围，或 R+W>I：invalid_usage，不用 Math.max 截断掩盖异常。
- 明确价格为 0 且所需用量完整：费用为 0，属于已定价。
- 超时、unknown 和没有 usage 的失败：金额未知，展示请求数，不能按 0 支出理解。
- 已返回 usage 的请求即使后续业务解析失败也统计费用；同一 receipt 多次 attempt 分别累计；origin=replay/imported 默认不进入实际运行费用。

## 6. models.dev 同步与模型匹配

### 6.1 同步方式

候选地址为 `https://models.dev/api.json`。本文未进行在线请求，端点、数据结构、计价单位、币种、使用条款和更新机制都需要阶段 5 在可联网开发环境核实后固定适配器与本地夹具。models.dev 是参考价格汇总来源，不能直接等同于供应商当前账单。

由后端管理员 POST 操作同步，打开页面只读本地缓存，不触发同步或推理。第一版只做手动同步，未来再按需求增加低频任务。

同步需要固定 HTTPS 主机、限制重定向目标、超时和响应大小、校验 JSON 与价格字段、串行化或互斥控制。使用项目现有 HTTP 防护方式；不开放任意抓价 URL，不向 models.dev 携带模型密钥。网络禁止或源失败时记录最后失败原因，保留旧目录及其成功时间。

解析在数据库事务之外进行，全量校验后原子发布新目录。无效项隔离并报告数量，不能将解析错误转成零价。空目录、异常大规模丢失或结构变化应拒绝自动发布，提示检查。可以使用 ETag/Last-Modified；304 不改变价格 hash。

### 6.2 映射策略

优先使用管理员明确指定的 source_provider_id + source_model_id。已确定官方供应商且模型 ID 完全匹配时可提供默认映射；第三方连接若在多个官方供应商下匹配，应让管理员选择。

第三方连接的本地 model ID 可以是别名，支持手动搜索官方模型并显示两边名称。模糊匹配只给候选，不静默应用。精确型号也可能有不同地域、上下文档位与批处理价格，第一版只采用适配器确认的普通调用基础档；存在影响当前请求的阶梯时提示不支持，不默认算准。

同步只更新参考目录；custom 配置不变。reference 模式在下次请求采用新目录价格，已记录快照不变。条目失效时使用最后成功价并标记 stale；没有历史成功价则未定价。页面始终显示最后成功时间，建议超过 7 天标记旧参考价，此阈值只是提示，不停止模型请求。

## 7. 后台 API 与界面

接口命名为建议，阶段 1 固定契约，沿用 adminHandler、CSRF、Zod 校验和 audit：

| 接口 | 作用 |
| --- | --- |
| GET `/api/admin/model-pricing` | 规则、有效价格、来源、归属和失效状态 |
| PUT `/api/admin/model-pricing` | 以 providerKey/model/upstreamRevision 保存整套规则；冲突返回 409 |
| POST `/api/admin/model-pricing/restore` | 恢复已选参考模型价格；映射无效时给出明确错误 |
| GET `/api/admin/model-price-catalog` | 本地目录搜索、候选和同步状态，分页且限量 |
| POST `/api/admin/model-price-catalog/sync` | 手动同步，返回变更、失败和失效数量 |
| GET `/api/admin/model-costs` | 指定时间范围内按币种、计费类型及连接／模型汇总 |

不复用 `/api/admin/models/:capability` 写入定价。第一版无需在线目录搜索，搜索只读本地数据。API 可为现有 modelsOverview 增量扩展共享费用聚合结果，避免两处不同算法。

页面安排：

1. 连接卡片提供“模型价格”，编辑面板显示请求模型、参考模型、模式、币种、四类价格、来源和同步时间。
2. 保存前显示完整有效价格。恢复参考价展示将采用的值及其时间，不进行模型试调用。
3. token 总览旁增加“费用统计”，分别显示实际 API 费用、尚无实际账单的完整估算、近似估算、部分金额以及订阅等价金额；按币种分组。
4. 能力统计的费用列显示来源及状态；连接、模型、提示版本作为完整 row key，避免同名模型碰撞。
5. 未定价、缺少用量、缓存未知、历史补算分别显示请求数和覆盖情况，可筛选定位。覆盖率分母明确为筛选范围内 live attempts，不冒充账单完整率。
6. 时间范围继续兼容 24 小时／7 天／30 天，按 attempt.started_at 归属；边界由后端统一计算，页面时间采用北京时间。

综合 API 金额按 attempt 优先选实际费用，否则选 complete/approximate 的估算；必须标注“实际 + 估算”。partial 单独展示已知部分，不能混入完整综合金额。实际金额与估算都不存在时保留未知计数。同一个 attempt 不能重复进入金额或调用总数；同一用途对应多个能力时不能把能力卡片简单相加形成全局总额。

## 8. 历史数据策略

默认保留历史原记录。缺少连接归属的旧 attempt 标为 legacy/unattributed，不从当前默认连接或同名模型推断供应商。

第一版先提供只读“按当前价格补算”预览，明确显示补算时间、选定价格版本、未归属数量、不能恢复的缓存明细，以及不代表当时实际价格。

可选持久化阶段采用单独的 backfill 结果表，保存 attempt_id、run_id、映射证据、价格快照、calculator_version、结果与计算时间，不覆盖原 attempt 快照、usage、cost 或回执状态。每个运行使用固定规则快照，不能一批中途读到新价格。

允许管理员提供有依据的旧记录映射，例如明确的连接独占时间段；只能生成候选并预览冲突，不按模型名自动归属。多解记录保持未归属。写入以 `(attempt_id, run_id)` 幂等，批量分页、可中断恢复、不跨长事务锁住回执；默认汇总不采用补算结果，管理员显式选择某次补算视图后另列金额。不同补算 run 不叠加。

迁移 0022 曾将旧 receipts 导入为一个 attempt，更早的重试明细可能无法恢复；补算文案必须说明这一限制。历史补算不调用模型、不调整预算、不解锁未知回执。

## 9. 分阶段实施与验收

各阶段独立实现、验证并提交 Git。涉及用户可见功能的阶段按 AGENTS.md 同步 SemVer、网站更新日志和使用文档。阶段性能力未完成时应明确文案，不提前宣称完整计费。部署迁移另按手动部署流程进行人工确认。

### 阶段 1：计价语义、契约与纯计算模块

- 固定 provider_key、billing_kind、价格覆盖模式、金额字符串和 estimate_status 契约。
- 新增建议模块 `providers/model-pricing.ts`、`providers/model-usage.ts`，先实现纯解析／计算，不接外部服务。
- 为已有 OpenAI 兼容和 Codex usage 建本地夹具；核实缓存与推理语义。
- 验证 1.6 USD 示例、零价、null、缓存不重复、推理不重复、缺少明细降级、非法用量、金额精度和边界。

完成标准：相同价格快照与用量产生稳定金额与原因；未配置、未知和免费三者可区分；无数据库或模型网络依赖。此阶段还不展示新费用功能。

### 阶段 2：持久化定价与请求快照

- 追加模型规则、参考目录占位结构、attempt 字段及必要索引的向后兼容迁移。
- 将 billingContext 贯穿实际 ModelSpec 到 paidRequest；默认别名解析为真实连接。
- 在 claim 事务中锁定有效价格；响应保存时计算费用；缺少配置时保持旧模型流程。
- 建内部定价读写方法、校验、revision 冲突及审计；暂可用测试／内部入口写规则。
- 不修改 logicalKeyFor、身份 generation、账号授权、budget service 与预算上限。

完成标准：两条连接调用同名模型记录不同价格；请求在途调价仍用原快照；重试用新快照；回执复用无新增费用；改价与改映射后旧回执仍能复用，unknown 不被重发。旧应用兼容新增可空列，迁移不更新历史金额。

### 阶段 3：费用聚合与查询 API

- 新建共享聚合层，以 live attempts 为事实来源，按连接、模型、币种、计费类型和用途拆分。
- 更新 modelsOverview 与契约，保留现有 token 统计行为。
- 支持实际费用优先、完整／近似估算、部分金额和未知覆盖；订阅金额单独统计。
- 追加管理员费用接口；验证时间范围合法、分页／筛选以及索引计划。

完成标准：混合实际金额与估算不丢项、不重复；跨币种不相加；同名模型不混供应商；全局总额只统计一次 attempt；删除或改名连接、切换默认后旧统计保持原归属。

### 阶段 4：手动定价与费用界面

- 实现价格编辑 API 与连接卡片入口，支持 custom 整套价格、恢复映射价格、审计与 409 冲突。
- 显示费用摘要、每模型费用、价格状态和覆盖情况；目录尚未接入时允许纯手动定价，并说明参考价暂不可用。
- 补充 admin UI 与契约回归，验证保存、刷新、空价与零价、USD/CNY、冲突提示、删除连接历史展示。

完成标准：管理员不用编辑文件或 SQL 即可给各连接模型设置价格；调价后新请求采用新值，历史费用不变；Codex 页面明确是 API 等价金额。

此阶段可作为手动定价 MVP 发布点；是否部署仍按正式发布流程单独决定。

### 阶段 5：models.dev 目录同步与默认映射

- 核实实际 API schema、价格单位与币种，补充冻结 JSON 夹具和适配器说明。
- 实现固定源同步、原子发布、失败保留旧值、失效条目、目录搜索及明确模型映射。
- 给已确认官方型号提供默认参考价，第三方别名提供候选和人工映射；纯手动价格不受同步影响。
- 验证 200/304、超时、非 JSON、结构变化、非法价格、条目消失、并发同步和重定向限制。

完成标准：同步不调用任何模型；打开页面不联网；错误不清空目录；custom 不被覆盖；reference 只影响之后请求；不支持的价格档位能清楚提示。

### 阶段 6：历史补算预览与可选持久化

- 先实现只读预览，按固定规则快照给出补算与未知覆盖。
- 确有需求再追加 backfill 结果表、dry-run/execute/resume 工具、映射预览和补算视图选择。
- 验证分批幂等、断点恢复、冲突映射拒绝、run 间不叠加、旧实际金额不变。

完成标准：补算可单独关闭，正常新请求计价仍可使用；不会发送模型请求或改变预算及回执状态；未归属历史不被强行分给当前连接。

### 阶段 7：统一验收与正式部署准备

- 复核完整代码与文档，测试各阶段组合行为、升级兼容、应用回退以及目录源故障。
- 在隔离环境跑完整检查，记录失败与复核，不能将相关测试通过写成全部通过。
- 按 `docs/manual-deploy.md` 准备版本、镜像、备份、迁移锁耗时评估、部署顺序和只读检查方案。
- 推荐先迁移、再 API/worker/web；各阶段迁移必须兼容旧应用。旧 worker 不写快照时新页面显示未知，不能套当前价伪造历史。
- 回退应用保留新增数据库结构与费用记录，不删除回执、不恢复旧数据库。

完成标准：新旧组件短期混用不破坏模型任务；只读统计与测试夹具金额一致；部署检查无需真实试调用；生产账号、模型、推理强度、并发和预算保持已授权设置。

## 10. 验证清单与维护文档

所有模型回归使用 `tests/setup.ts` 的本地 stub、独立临时数据目录和虚构密钥，测试库名以 `_test` 或 `_ci` 结尾，隔离网络，保持安全阀关闭，不加载生产 `.env`。models.dev 回归使用本地 HTTP 替身或冻结文件，完整测试期间不访问外部目录。

实施阶段至少覆盖以下场景：

| 场景 | 必须满足 |
| --- | --- |
| 同名模型来自两个连接 | 归属和价格独立 |
| default 从 A 切到 B | A 历史金额不变，新请求属于 B |
| 改价／改参考映射 | 不改 generation，不绕过旧回执 |
| 响应解析失败后重试 | 第一次已返回用量计费，第二次单独计费 |
| unknown 结果恢复 | 仍遵守原恢复流程，不凭估算认定免费 |
| 同一回执多消费者 | 只统计真实 attempt，不按消费者重复计费 |
| 缓存与推理 | 输入子集不重算，推理不追加输出费用 |
| 无缓存明细 | 近似金额有原因，缓存率仍未知 |
| 零价格与空价格 | 免费和未定价可区分 |
| API 与订阅、USD 与 CNY | 分类、币种分别汇总 |
| reference 更新／custom 编辑 | 各自只影响新请求，快照不可变 |
| 连接改名、删除、模型换名 | 历史可解释，不能按当前注册表重新归属 |
| 历史导入与补算 | 默认不混入新请求统计，补算不覆盖原值 |
| 并发调价和目录同步 | 一条请求只使用一致的一版有效价格 |
| 返回内容或计价异常 | 已收到响应仍保存，不因计价错误重发模型 |

每个实现阶段运行适用的相关回归，以及 AGENTS.md 要求的完整类型检查、隔离数据库测试、网页构建与网页测试；站点启动后运行冒烟。每次依据实际改动选择针对性验证，并记录全套测试的本次结果与既有基线。

用户可见功能实现时同步 `README.md`、`docs/chatgpt-auth.md`、`docs/soymilk-operations.md` 和 `industry/changelog.json`；阶段进度与验证写 `docs/changelog.md`。价格、费用与覆盖率属于实时数据，操作文档只提供查询方式，不把某次统计写成永久现况。
