## 本站适配决定

### N1／N2

查询在 URL 解码后拒绝 C0／DEL 控制字符。严格入口保留未知／重复拒绝；站点宽松入口保留首值优先，控制字符即使出现在未知或后续重复参数中也拒绝。主题路径的控制字符拒绝、page/1 跳转正确编码。OG 只读自有键，不能命中对象原型。请求头按不区分大小写覆盖默认值；带引号字符集和 NUL 文本替换不改变二进制 body。

备份使用 `PGUSER`／`PGPASSWORD` 仅传给 `pg_dump`，移除 URL userinfo 和 query 凭据；非凭据 query 保留原始字节编码与 `+` 的 libpq 语义。对象存储仍沿用原凭据来源。dump 失败只报告固定操作与退出码，不保留原错误的 argv、stderr 或 cause。这不宣称环境变量本身不再是凭据。

### N3

翻译直接使用新恢复机制，不再读取 `TRANSLATION_RECOVERY_ENABLED`。已收到但片段对齐／中文结果不可用的响应被业务拒绝，沿原逻辑身份有限恢复；有效译文和有效回执完成同事务写入。失败计数与业务拒绝也同事务，每文章版本最多三次真实失败、五分钟退避，持久恢复不清零。无请求的超长首段跳过；预算、停机、在途、unknown 等待不扣次数。新旧 attempt 不能相互覆盖。

复审补齐 JSON／schema 解析失败的同一事务边界：翻译延后通用模型层的输出拒绝，由翻译失败计数事务一起提交。强制事务失败后回执仍为 received，再次消费不额外付费；已完成译文不被迟到异常改为失败，旧 attempt 也不能完成或拒绝较新的在途／unknown 响应。

一轮可以包括原批次、拆分与补译，**三轮上限不等于三次付费请求上限**，费用以 `receipt_attempts` 为准。已有消费者及已收响应继续消费；不重开已有 skipped、partial 或三次终态。既有超过 30 分钟自动放行 unknown 一次的恢复保持，未获释放前不能以新身份重发。显式语言声明优先，未知语言再用 Han 与假名／韩文等判断，日文汉字不再直接视作中文。

### N4

后台 `/admin/runs`、定时告警和周报统一使用新证据逻辑，不再读取 `SOURCE_HEALTH_EVIDENCE_ENABLED`，删除原分组日报及固定七天静默周报的旧分支。修复事项按信源／问题逐项报告，后台保存的逐项忽略对日报生效，静默信息只进入周报。飞书发送仍受原安全阀保护，本轮保持关闭。

节奏最多回看 90 天，至少四个产出日，静默时长**超过**中位间隔的四倍才判逾期，恰好四倍不算；产出日按北京时间计算。首次导入折算一天，包含非主来源 discoveries。历史不足、从未收到和低频安静分别解释，只对近七天无发现且加入超过七天的安静源补查节奏。

后台新增 `POST /api/admin/followups/:key/dismiss` 与 `/restore`，要求管理员、CSRF 和审计理由；较新的故障时间证据重新打开，忽略／恢复写入与审计通过同一事务和互斥锁完成。积压事故从首次检测起算，并固定观察窗口，关闭采集／模型开关或文章老去不伪造恢复。放弃通知的人工处置显示结束跟进，不显示恢复。

`alerts.state` 直接持续保存事故与范围，无需迁移，也不再依赖或新增切换所需的 `evidence` 标记。已有标记可自然兼容并忽略，不重置事故时间或提醒节奏；旧 service 级额度事件有证据时迁入具体 scope，迁入不重复宣布或伪报恢复，缺证据时保守保留。所有事故始终按真实证据判断，不再提供新旧模式切换。

额度拒绝按连接／供应商／账号／配置／请求型号证据跟踪，归属只读每次 `receipt_attempts.pricing_snapshot.providerScope` 的不可变快照。`receipts.request` 会在同回执重试时变化，不能用它回填旧 attempt 的身份；旧失败缺少 scope 时保持未知范围，带新 scope 的成功或同样缺少 scope 的成功都不能证明旧配置恢复。模型和非模型服务的新请求均冻结 scope；非模型使用完整 unpriced 快照，不据此新增模型费用估算。只有具备 scope 对象证据、同一范围内且开始时间晚于拒绝完成时间的成功调用才能关闭拒绝，旧在途成功和其它连接／型号成功均不能关闭；弃用旧型号只降低当前影响。旧 service 级告警缺证据时保守保留。

查询成本边界：`articles` 已有 `(source_id, discovered_at DESC)` 和 `discovered_at` 索引；`article_discoveries` 目前只有 `(article_id, source_id, via)` 主键，缺少按来源／发现时间的索引。90 天限制只适用于节奏证据，判断“从未收到”的 `output_sources` 仍需汇总全部既往产出；本轮改为一次汇总，避免每源重复相关扫描，但不能宣称全程仅扫描 90 天或必走索引。本轮不加迁移。

一次性成本脚本 `work/upstream-20261020/health-plan.ts` 限专用空库，生成 64 源、521 篇文章、24,581 条发现记录并核对窗口边界。首次执行保留“三个有效产出日”的断言，暴露 UTC 数据库 session 下原预筛丢失北京时间起始日 00:00—08:00 的问题；已将产品及脚本的候选预筛统一为明确的北京时间日界 `Date`，并新增午间核验的文章／发现入口回归，未放宽边界断言。

脚本中的 `source-output-history` 与 `quiet-source-rhythm` 两项 EXPLAIN 与当前对应 SQL 条件一致，分别覆盖既往产出汇总及安静源节奏；三次 `sourceHealth()` 计时才包含完整诊断流程，两个代表计划不能替代完整流程耗时，更不能代替生产测量。最终专用空库中，完整诊断三次为 **103.964／85.057／82.265 ms**；既往汇总为 **11.131 ms**、298 shared-hit blocks，节奏为 **73.577 ms**、312 shared-hit blocks。两项均对发现表使用顺序扫描；没有据这组缓存已热的合成结果承诺生产延迟或创建索引。

### N5／N6／N7

网页时间排序仍不搜索正文；网页相关度保留正文子串；API／MCP 只对正文纯英文数字词增加词首，标题摘要继续子串匹配，`ragged` 仍可命中 `rag`。六词／LIKE 转义／40 条每页／50 页／2,000 有界计数保持，相关度排序考虑全部匹配候选。本站没有上游 `seat` 字段，本轮以通过公开门槛的 `p.selected` 作为精选优先级，其后质量、时间、ID；不引入席位字段、迁移或新精选策略。

日期按来源偏移解析，保留本站 ISO 纯日期 UTC 语义；英文月份、at／AM／PM 和日历校验不依赖进程 TZ。日期标题同年显示月日、异年补年份，不改数据库时间与排序。Atom `updated` 只记录 sourceUpdatedAt，首发未知继续走本站收录时间归档。HTML 文字解码直接声明已存在的 `entities@4.5.0` 依赖，不升级其余依赖树。SVG 仅保留来源文字说明，不开放 SVG 执行。Jina 协议 warning 仅在协议头解释，已付费错误页保持 received 以便本地复查，不自动另购。

搜索成本检查捕获实际相关度 SQL 及参数，用仅移除新增并列排序项的查询作对照。在 2,005 个合成候选下，新／原并列顺序执行耗时分别为：单词优化 **22.150／21.726 ms**，多词 **20.695／21.311 ms**，单词加标签筛选 **19.929／20.913 ms**。两侧计划均先考虑全部候选再取 40 条，返回有界计数 2,000；跨页不重复、精选优先于普通高分、质量与 ID 并列顺序均通过断言。这是同库单次对照，不据此宣称性能提升或生产延迟。

### N8

资金拒绝冷却直接生效，不再读取 `PROVIDER_QUOTA_COOLDOWN_ENABLED`。可靠资金拒绝触发 15 分钟冷却，普通 401／403／429 不触发。scope 独立于付费 logical key，包含连接、供应商、账号和配置不可逆指纹及请求型号，持久写入 settings；复用及 unknown 检查优先于新占位冷却检查，不改变付费身份。旧入口缺少 scope 时保留原拒绝行为，不伪造账号范围。

到期以同一实际业务请求进行单探测，pending／unknown 探测跨重启继续互斥，原 unknown 先走既有核账恢复；普通探测失败至少再等一分钟，后续同 scope 成功才解除。拒绝 revision 防止旧在途成功误清新冷却。覆盖模型、embedding、Jina、SocialData、Dajiala；Codex 原账号 blockedUntil 保护继续保留，不自动切换账号／型号。
