## 采用的行为与保护边界

### U1：登录页不进入新闻材料

`content/extract.ts` 只根据完整 URL 路径段判断登录／注册等页面，不检查正文关键词，所以讨论密码管理或登录流程的真实文章仍保留。正常文章地址跳转到登录路径后直接返回未确认正文，不再付费读取同一登录页。原始地址本身包含 `register` 且只是规范化尾斜杠的情况继续提取，避免上游初版的误伤。

`sources/web-list.ts` 同时过滤 HTML、Markdown 列表里的登录／注册导航，并拒绝原生列表或详情抓取跳到登录页。详情入口也受保护，避免把登录标题和描述写进文章。判断不会匹配 `/auth-for-agents`、`/authors/...` 或查询参数中出现的 `/login`。本轮不重写历史材料、版本、消费者或付费回执。

回归覆盖：足够长、旧提取器会接受的登录表单；真实文章正文；尾斜杠规范化；HTML／Markdown 导航；完整路径段边界；详情元数据；禁止追加 Jina 请求。

### U2：有效会话直达后台

`/api/auth/login` 已登录时使用既有 `sessionPrincipal()` 和 `safeReturn()` 直接跳向后台目标。`/admin/login` 使用请求自己的 Cookie 查询 `/api/admin/me`，登录有效则返回目标页面；匿名或身份查询失败时仍能看到密码表单。网页目标在 URL 规范化后须属于 `/admin` 目录，`/administrator`、目录穿越、外站、协议相对地址和登录页自身均回到 `/admin`，避免循环。

复核新增的 API 会话检查时，同时补齐既有边界：Cookie 按项解码并忽略损坏项，无关畸形 Cookie 不阻断有效身份，损坏的会话值不被接受；API 的 `safeReturn()` 也先规范化路径，拒绝跳出后台和登录页自身。保留代理传入 HTTP(S) 完整地址后只取站内后台路径的已有兼容，因此绝对地址不会成为跨站重定向。

上游登出 415 的根因是解析器位于登录专用插件作用域；本站密码登录与登出已经共享解析器，因此不做无效结构迁移。真实 HTTP 验收补充浏览器相同的 `application/x-www-form-urlencoded`，以及 16 KiB 上限在销毁会话前生效的断言。
