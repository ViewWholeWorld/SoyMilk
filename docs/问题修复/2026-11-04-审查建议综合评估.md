## 3. 评估效果的共同方法

### 3.1 先核对运行条件

以下项目不能只靠静态阅读决定。先在不读取密钥、不连接生产数据库和不调用真实模型的前提下核对生产入口、模型路由、备份状态、并发环境变量和发布方式。生产检查需要脱敏输出。

- `SEC-02`、`SEC-03`、`SEC-05`、`SEC-07` 需要确认 API、ingest、HTTP 会话和出口代理的实际拓扑。
- `AUTH-02` 需要确认 ChatGPT 是否仍在生产模型路由中。
- `BUD-04`、`BUD-09`、`OPS-01`、`OPS-03`、`OPS-13` 需要确认开关、备份、表规模和查询计划。
- `OPS-11` 需要统计近几次发布的漏检缺陷和定向验收成本。
- `CODE-01` 需要确认 Node 24 实际执行路径是否调用了只存在于 Node 26 类型中的 API。

### 3.2 高影响代码项

在隔离数据库、虚构密钥、关闭采集和模型开关的环境中，优先验证以下行为。

- `SEC-01`、`SEC-04` 覆盖登录限流和鉴权前大请求。
- `JOB-01`、`JOB-02`、`JOB-04`、`JOB-05`、`JOB-06`、`JOB-08`、`JOB-09` 覆盖未知回执、事件合并、报告公平推进、热度重算、批次恢复和并发重入。
- `BUD-01` 至 `BUD-08` 覆盖确定拒绝、回执状态、预算缺行、usage 统计和重试付费边界。
- `COLL-01` 至 `COLL-06`、`COLL-09` 覆盖采集轮次、候选上限、URL、日期、相对链接、时区和 shutdown 状态。
- `PUB-01` 至 `PUB-05` 覆盖隔离信源、发布闸门、游标和 MCP 请求大小。
- `OPS-02`、`OPS-04` 至 `OPS-09` 覆盖迁移兼容、发布标签、topics、容器权限、密码和连接池。

每个验证都要记录触发输入、预期不变量、实际结果、失败类型和是否产生付费 attempt。未知结果不能当作通过。

### 3.3 提示词评估

`PROMPT-01`、`PROMPT-02`、`PROMPT-04` 先运行装配和 schema 契约检查。检查未解析变量、冲突长度范围、枚举键、JSON 形状、revision 原样返回、结构对象层级和 fact 字段完整性。

`PROMPT-03` 使用[精选评分与校准](../内容管理/精选评分与校准.md)中的人工标注流程。开发集用于修改规则，留出集只在候选版本冻结后运行。报告准确率、查准率、查全率、覆盖率、错误类型、分层结果和门槛扫描。两次模型评分相近不能单独证明提示词改进。
