# 3.5.2 后台大模型配置与统计优化方案

状态：待实施。本文只记录优化方案，不代表功能已实现或已部署；当前使用方式仍见 [3.5.1 模型定价与费用](model-pricing.md)。

## 1. 定位与优化目标

**提供基于已获取数据的参考统计，让用户感知调用规模、模型表现和大致费用；允许数据不完整，不追求账单级核算。**

把“怎么配置模型”和“模型用了多少、表现如何、大致花了多少”分成两个页面。调用用量与费用都默认按“供应商 + 模型型号”汇总；获取不到的数据显示未知，不为了追求完整性增加对账、推算或复杂管理流程。

| 当前问题 | 3.5.2 处理方式 |
| --- | --- |
| 模型、价格、token、费用、历史补算挤在一页 | 拆成“大模型配置”和“模型统计”，各自按标签切换 |
| 同一个模型出现很多行 | 同一供应商的同一型号合成一行；不同供应商分别展示 |
| 提示版本和隐藏维度拆散统计 | 提示版本从普通统计移除；用途、连接、价格状态不参与默认分组 |
| 费用列表充满“未定价或缺少用量” | 统一显示“金额未知”，纯未知组默认收起，只显示数量摘要 |
| 辅助指标、筛选和操作太多 | 默认只保留常用指标与筛选，排查信息按需查看 |

本次改动集中在页面、聚合查询和展示，并补充供应商归属与筛选。不调整模型选择、账号、推理强度、并发、预算、回执和重试行为，不自动执行历史补算。

## 2. 现有问题依据

依据仓库代码与用户截图核对，截图中的数量不作为实时状态。

最近核对：北京时间 2026-10-16，远端 `main@7519528`（应用版本 `3.5.1`）。以下页面拆分、独立供应商记录及简化费用分类均为待实施改动。

- `apps/web/app/routes/admin/models.tsx` 的 loader 同时读取能力概览、连接、定价、费用、参考目录、补算运行及可选补算详情，打开配置页就加载大量统计数据。
- `packages/backend/src/admin/models.ts` 按用途、模型、提示词版本、连接、请求型号、计费类别和币种等字段分组。耗时、成功率、token 本身是指标；截图中的多行主要来自额外分组维度及空值差异。
- `packages/backend/src/admin/model-costs.ts` 同样按连接、型号、用途及费用相关字段拆组；前端把大量无金额项平铺，导致列表过长。
- 当前费用接口同时查询汇总和请求明细，前端仅用折叠区域隐藏明细；本次需改为打开明细时才查询。当前还单列部分估算金额，本方案将其在普通统计中归为金额未知，保留原始记录和高级明细。
- 现有 `provider_key` 和 `provider_label_snapshot` 表达连接或预设来源，不是独立的服务供应商。参考价供应商也不能直接作为中转平台的归属。

因此应在查询层减少分组，并真正分开配置与统计的加载。只隐藏前端行或把长列表搬到新页面不够。

## 3. 页面设计

### 3.1 大模型配置：`/admin/models`

保留现有入口，提供两个标签，默认打开“模型与能力”。

| 标签 | 内容 |
| --- | --- |
| 模型与能力 | Codex 账号、API Key 连接、供应商归属、默认连接、能力模型分配及推理强度 |
| 模型价格 | 按连接与请求型号编辑参考价或自定义价，搜索和同步参考目录 |

原“各项能力与调用统计”改为“能力模型分配”，保留能力、当前连接/型号、推理强度和切换操作，删除其下统计表。切换理由、审计及已有配置来源信息保留，历史切换记录默认折叠。

配置页提供“查看模型统计”链接；移除时间范围、用量、费用和补算表单。SelectBench 仅保留已有独立入口。首轮处理进度及预算恢复状态移到统计页，仅在进行中或异常时显示简要状态。

价格标签、参考目录和价格编辑所需数据在使用时加载，不能仅隐藏组件而仍在首次打开时全部请求。

### 3.2 模型统计：`/admin/model-stats`

后台导航新增“模型统计”，与“大模型配置”并列。默认打开“调用与用量”，另设“费用”标签。

```text
模型统计                             [返回大模型配置]
时间：最近 24 小时 / 7 天 / 30 天 / 自定义（北京时间）
筛选：供应商、模型                     [更多筛选] [刷新]

[调用与用量] [费用]

调用与用量：
  总调用、成功率、已知输入/输出 token
  供应商/型号表：调用、成功率、耗时 p50/p95、输入/输出 token、缓存率

费用：
  API 参考费用、订阅 API 等价金额（分别按币种展示）
  金额未知 N 次
  供应商/型号表：调用、参考费用、金额未知次数
  纯未知组摘要 + [显示金额未知项]
  费用仅供参考，未知金额未计入
  [高级：历史费用补算]
```

默认只保留时间、供应商、型号筛选；连接和用途放“更多筛选”，不另做能力与用途两套筛选。费用页不新增面向估算状态、覆盖类别等内部概念的筛选。现有高级明细中的筛选可继续使用。

每个标签使用一张供应商/型号汇总表、一套分页，默认每页 20 行，按调用次数降序。同一次数按供应商 ID、型号稳定排序。不增加跨币种费用排序或多层连接/用途分析表；需要排查时，通过连接/用途筛选缩小范围，并尽量复用已有请求明细入口，附带供应商、型号和时间条件。缺少现成入口时只补一个简单明细视图。

### 3.3 时间与刷新

- 调用与费用都按 attempt 的 `started_at` 查询，范围为开始包含、结束不包含；自定义日期按北京时间换算，结束日包含整天。
- 单次页面加载统一计算所选时间范围，各查询使用相同边界。快捷范围随普通刷新、切换标签或重新查询更新；自定义日期保持用户选择的日期。
- URL 保存标签、快捷范围或自定义日期及筛选，方便返回和分享。无需把快捷范围冻结为精确时间戳，也不增加“更新到现在”按钮。
- 筛选、时间范围或“显示金额未知项”变化时重置页码。页面可显示最近更新时间；在途请求完成及滚动窗口变化引起的小幅数字变化属于正常情况。
- 使用普通聚合查询，不要求新增可重复读事务、跨请求快照或冻结报表机制。汇总必须来自完整筛选范围，不能把当前页的小计算成总计；前端避免旧筛选结果覆盖新筛选结果。

## 4. 供应商归属与分组

### 4.1 供应商只做必要记录

供应商指实际提供调用服务的平台。例如通过 YosHub 调用 `gpt-6-luna`，供应商是 YosHub；模型原厂和参考价来源可以是 OpenAI。同一供应商可以对应多条连接。

连接编辑增加供应商选择，支持选择已有供应商或新增。使用轻量表 `model_suppliers` 保存稳定 ID、名称和基本去重键；名称去首尾空格、合并连续空白并统一大小写后判重，重复创建返回已有记录。官方默认项使用固定标识，避免同一官方供应商重复创建。

官方识别可复用 `model-billing.ts` 的已确认接口规则，但参考目录的地区标识不直接作为供应商 ID；例如阿里云国内与国际参考项映射同一服务供应商，地区和不同价格仍由连接区分。保存连接时校验所选供应商存在。

本期只提供查询与新增，不做独立供应商管理页、改名/停用流程、版本冲突控制、专用审计或供应商合并。连接配置变更沿用已有校验和审计机制。

- 连接保存可空 `supplierId`。已确认的官方接口可提供默认选择；Codex/ChatGPT 对应 OpenAI。中转和自定义接口由管理员指定，不按模型名或参考价映射猜测。
- 新 attempt 在保存价格快照时一并记录供应商 ID。统计名称从供应商表读取；本期不增加独立名称历史管理。连接后来换供应商不改变旧请求的归属，删除连接不丢失请求上保存的 ID。
- 历史请求没有供应商记录时，仅应用明确固定的历史标识映射，例如 `subscription:codex`、`subscription:chatgpt` 对应 OpenAI；其他显示“供应商未知”。不根据当前连接配置反推历史，不新增批量回填流程。
- 筛选提供“全部供应商 / 指定供应商 / 供应商未知”。旧连接编辑请求省略 `supplierId` 时保留已有归属，显式 `null` 才清除；已保存的 `null` 不在调用时自动覆盖。环境默认和预设连接仅沿用已确认的官方识别规则。

供应商归属只是统计元数据，不改变连接 generation、逻辑请求键、定价规则、回执复用，也不触发模型调用。

### 4.2 两个标签共用分组规则

默认分组键为 `(effectiveSupplierId, requestedModel)`。供应商按上面的请求记录或固定历史映射取得；型号采用 `coalesce(a.requested_model, a.model)`。调用、费用与筛选共用同一解析逻辑。

- 同一供应商、同一型号，多个连接、用途、提示版本和价格状态全部合并。
- 不同供应商的同名型号分别展示；不同型号或别名不按相似名称合并。
- 缺供应商时归入“供应商未知 + 型号”；型号也缺失时显示“型号未知”。未知组只表示缺信息，不断言这些请求来自同一家供应商。
- 连接、用途用于筛选和明细，提示词版本不出现在普通统计里。币种与计费类别只影响费用行内的金额分项，不拆主行。

例如 YosHub 主、备用连接调用 `gpt-6-luna` 合成一行；OpenAI 的同型号另列一行。`group_article`、`group_signal`、`group_story` 默认合并，选择具体用途后再查看对应结果。

## 5. 调用与用量口径

直接聚合筛选范围内的原始模型调用 live attempts，排除 imported/replay、SelectBench 和其他非模型请求。不要在浏览器合并分页后的旧统计行。

| 指标 | 口径 |
| --- | --- |
| 调用次数 | 每次实际 attempt 计一次；重试分别计，复用回执不新增，缺用量仍计调用 |
| 成功率 | 收到响应的 attempt 数 / 总调用数，沿用现有 `received` 状态；提示“收到响应不代表业务处理成功”，结果未知不算成功 |
| 耗时 p50/p95 | 从合并后的有效已完成耗时样本重算，无样本显示未知，不平均旧分位数 |
| 输入/输出 token | 分别累加已报告的有效值；全部缺失显示未知，部分缺失标记“部分数据” |
| 缓存率 | 对输入总数与缓存读取数同时有效的请求计算 `sum(cacheRead) / sum(inputTotal)`；分母为零或无有效样本显示未知 |

成功率与缓存率不能直接平均旧行百分比。缓存率分子、分母必须使用同一批请求，缓存缺失不能当作未命中；复用已有用量规范化与校验，排除负数、缓存大于输入等非法样本。明确的 0 与未知不同。

例如请求 A 输入 100、缓存 80，请求 B 输入未知、缓存 50，缓存率为 `80 / 100 = 80%` 并标记“部分数据”，不能计算为 130%。计算所需计数和分母留在后端，前端只接收展示值及必要的缺失/部分标记。

主表不要求展示逐项覆盖率、缓存读写完整度、非缓存输入、推理 token 等辅助指标，也不新增对应统计卡片。已有原始用量可在请求明细查看；推理 token 不重复加入输出总数。

零调用时成功率显示“—”；无可用数值显示“未知”。保留已知数据，避免一个字段缺失导致整行消失。

## 6. 费用口径与展示

### 6.1 只区分可用金额与金额未知

费用基于已保存的单次请求金额和价格快照，沿用现有计算器；统计页不拿最新单价重新计算历史用量。

| 单次请求情况 | 参考费用处理 |
| --- | --- |
| 有有效实际金额 | 优先计入，估算金额不重复累计；用量缺失不影响已有实际金额 |
| 没有有效实际金额，有完整或近似估算金额 | 计入参考费用 |
| 只有部分估算金额，或没有可用金额 | 统一计为“金额未知”；部分数值和原始原因仅在明细保留 |

有效金额要求数值合法、非负且币种明确，复用现有金额精度和校验；明确的 0 正常保留。`partial` 即使有部分数值，也不加入参考费用。缺价格、缺用量、超时、响应丢失或其他异常不另拆费用类别，不猜算、不补 0。

每次请求只计一次，满足“总调用数 = 可用金额请求数 + 金额未知请求数”。页面只展示参考费用与金额未知次数，不新增覆盖率、部分金额或实际/近似数量卡片；原始状态和费用字段不改写。

例：同币种、同计费类别的四次请求，实际金额 0、完整估算 1、部分估算 0.2、金额缺失。参考费用为 1，金额未知 2 次；0.2 只保留在原请求明细。

### 6.2 合并与未知项展示

每个供应商/型号一行，使用各连接、各请求已经保存的金额求和，不设置供应商统一单价。USD/CNY 分开列示，API 参考费用与订阅 API 等价金额分开列示，不换汇混加，不把订阅等价金额当作真实扣款。

历史计费类别为空但已有可用金额时，保留“计费类别未知”金额分项，不默认归为 API 或订阅；其他已明确币种按原币种分列，币种缺失时金额仍为未知。

- 顶部显示完整筛选范围的参考费用及金额未知次数，并注明“费用仅供参考，未知金额未计入”。
- 同一组合既有可用金额又有未知金额时，仍是一行，显示参考费用及“另有 N 次金额未知”。
- 默认隐藏全组金额未知的行，显示“另有 M 个供应商/型号组合，共 N 次金额未知”。勾选“显示金额未知项”后纳入同一张表、同一套分页，不再建立独立未知列表。
- 显示或隐藏纯未知组只改变表格行的可见范围，不改变顶部汇总的统计范围。顶部未知数包含所有组，不能只累计当前页。
- 全部金额未知时显示“当前范围金额未知”及次数，保留查看这些组的入口，不显示总费用为 0。已有有效零费用的组正常展示。
- 范围内没有调用时显示“暂无调用”，与有调用但全部金额未知区分。

连接不稳定导致供应商可能已经扣费、本站却没有收到用量或金额时，统一记录为金额未知。调用次数保留，价格快照保留，不把可能成功的调用标成已确认成功。后续重试作为独立 attempt，新请求费用不替代旧请求未知金额。

本次不增加供应商账单查询、自动对账、账单导入、金额分摊、原因分类体系或为补齐统计而重发请求的机制。

### 6.3 历史补算仅保留高级入口

现有历史补算移到费用标签的高级入口，打开后才加载。保留已有预览、执行和结果查看流程，本期不增强功能，不自动执行，不在默认统计中混入补算结果。

补算不能恢复丢失的用量或真实历史报价。查看补算时仍独立选择一轮结果，不与原金额或其他轮次相加；本次不改变已有安全边界和原始记录。

## 7. 实施范围

### 7.1 页面与接口

| 范围 | 本期工作 |
| --- | --- |
| 前端路由 | 保留配置页，新增统计页及导航；按标签加载数据 |

主要涉及 `apps/web/app/routes/admin/models.tsx`、新增统计页路由、后台导航、费用组件，以及 `packages/backend/src/admin/models.ts`、`model-costs.ts`、相关 API 和契约。归属记录涉及连接配置、`providers/model-billing.ts` 和回执领取链路。

### 7.2 持久化与必要兼容

新增轻量供应商表，并给 attempt 增加可空供应商 ID；使用向后兼容的增量迁移，不修改 `0045`—`0047`，不级联删除历史请求。供应商只保存必要名称和标识，不保存密钥或完整连接信息。旧请求缺归属按未知规则读取，不批量推断回填。

旧接口先核实实际调用方，再确定最小兼容范围。当前维护文档确实使用 `modelsOverview().tokenSummary` 只读检查，实施时应保留这项能力或同步更新这些明确使用方；能力切换接口保持行为。无需为了假设中的消费者长期维护两套完整统计结构。

旧配置入口继续可用；已有统计、价格及补算链接按实际参数跳转到对应页面/标签，保留适用的时间和筛选参数。新统计契约允许未知值，不为了复用旧数值类型把 `null` 转成 0。

### 7.3 实施顺序

1. 补充最小供应商归属，确定两个标签共用的分组与参考费用口径。
2. 拆分配置读取与统计读取，完成页面、标签和导航。
3. 实现供应商/型号聚合、基本指标与普通筛选分页。
4. 精简费用展示，折叠纯未知组，迁移高级补算入口。
5. 完成隔离验证并同步实际使用文档。

本文阶段仅修订方案，不提升版本号、不写已发布公告。功能完成后按仓库规范更新 `README.md`、`docs/model-pricing.md`、`docs/soymilk-operations.md`、网站更新日志和版本；正式迁移及部署仍遵守现有流程。

## 8. 验收标准

| 场景 | 预期结果 |
| --- | --- |
| 打开配置页或统计页 | 只加载当前任务/标签所需数据，未打开价格、费用和补算不预加载 |
| 同供应商、同型号存在多连接、多用途、多提示版本 | 默认合成一行；指标缺失和价格状态不拆行 |
| 不同供应商调用同名型号 | 分别展示；供应商/型号筛选同时适用于调用与费用 |
| 供应商无法确定、连接更换供应商或删除 | 未知独立成组；已保存的历史归属不跟随当前连接变化 |
| 供应商选择与新增 | 多连接复用同一 ID，基本去重有效；旧连接编辑省略字段不清空归属 |
| 重试与回执复用 | 实际 attempt 分别计数，复用不新增；筛选后不重复累计 |
| 合并成功率、耗时和缓存率 | 从有效原始样本计算，不平均旧百分比或分位数；缓存率分子分母使用同一批请求 |
| 用量全缺失、部分缺失、明确为零 | 分别显示未知、部分数据、0；推理 token 不重复计入输出 |
| 实际、完整估算、近似估算、部分估算与未知混合 | 每次请求最多取一个可用金额；部分估算归金额未知，原始记录保留 |
| 响应丢失、可能扣费或仅用量缺失 | 无可用金额就未知；已有有效实际金额仍计入参考费用，不自动补算或对账 |
| 同组存在不同币种或 API/订阅等价费用 | 主行不拆，金额分项展示，不混加、不冒充真实订阅扣款 |
| 隐藏/显示纯未知组、翻页或全部未知 | 始终一套表格分页；顶部汇总来自完整筛选范围，全部未知不显示为 0 |
| 快捷范围刷新、自定义日期及在途请求完成 | 普通刷新可更新快捷范围；自定义按北京时间；允许数字随新数据变化 |
| 原有维护查询、价格配置和历史补算 | 实际使用入口继续有效或同步迁移；历史快照不改写，补算结果独立查看 |

实现阶段按 [隔离测试说明](testing.md) 和 `AGENTS.md` 完成相关聚合回归、类型检查、后端及网页检查；使用本地替身与隔离测试库，不访问生产库或真实付费模型。验证重点是分组正确、未知不补零、不重复计数和页面加载简化，不增加账单对账类验收。本文档阶段仅检查内容一致性、链接和差异格式。
