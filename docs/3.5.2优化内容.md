# 3.5.2 后台大模型配置与统计优化方案

状态：待实施。本文只记录优化方案，不代表功能已实现或已部署；当前使用方式仍见 [3.5.1 模型定价与费用](model-pricing.md)。

## 1. 优化目标

把“怎么配置模型”和“模型用了多少、表现如何、花了多少”分开。默认展示按模型汇总的结果，需要排查时再查看连接、用途和单次请求。

| 当前问题 | 3.5.2 处理方式 |
| --- | --- |
| 模型、价格、token、费用、历史补算都堆在一个页面 | 拆成“大模型配置”和“模型统计”两个独立页面；页面内部按任务切换标签 |
| 同一个模型出现很多行 | 调用统计默认一个型号一行；提示词版本、用途、连接和费用字段不再拆分默认行 |
| 提示版本占空间，日常没有使用价值 | 从普通统计中移除，保留原始记录供请求诊断和评测追溯 |
| 费用列表大量重复“未定价或缺少用量” | 已知金额优先展示，纯未知项折叠为摘要；按需展开具体原因和明细 |

本次重点是页面职责、查询聚合和信息展示，不调整模型选择、推理强度、账号、并发、预算或回执行为，也不自动执行历史费用补算。

## 2. 现有实现与问题原因

依据当前仓库代码及用户截图核对，不把截图中的数量写作实时状态。

1. `apps/web/app/routes/admin/models.tsx` 的 loader 同时读取能力概览、连接配置、定价、费用、参考目录、补算运行，以及可选的补算详情。页面打开就加载多个不同任务的数据，配置操作也容易带动统计重新查询。
2. `packages/backend/src/admin/models.ts` 当前按用途、模型、提示词版本、连接、请求型号、计费类别、实际币种和估算币种分组。同一模型的多版提示词、旧记录缺少连接或币种、实际金额和估算金额的字段差异，都会形成多行。
3. 耗时、成功率、token 和缓存数本身是聚合指标，并非当前 SQL 的分组字段。截图中看似因为指标不同而分行，实际是上述隐藏维度和提示版本拆分后的结果。
4. `packages/backend/src/admin/model-costs.ts` 又按连接、型号、用途、计费类别及两种币种字段组合分组；不同用途和空值使费用列表继续增长。
5. `apps/web/app/features/admin/model-costs.ts` 没有金额时统一返回“未定价或缺少用量”，没有区分缺价格、缺用量和用量异常。纯未知项与有金额的项目平铺，掩盖了真正可读的费用。

因此需要同时拆页面、减少默认分组、改进未知值表达。只在前端隐藏重复行，或者只把原来的长列表搬到新页面，都不能完整解决问题。

## 3. 页面拆分

### 3.1 大模型配置：保留 `/admin/models`

保留已有入口，页面内提供两个标签，默认打开“模型与能力”。

| 标签 | 内容 |
| --- | --- |
| 模型与能力 | Codex 账号、API Key 连接、默认连接、各能力当前模型、推理强度、切换操作 |
| 模型价格 | 按连接和请求型号设置参考价或自定义价；参考目录搜索、同步和价格状态 |

调整细节：

- 原“各项能力与调用统计”改为“能力模型分配”，使用紧凑列表：能力、当前连接/型号、推理强度、配置来源、切换。移除其下所有调用统计表。
- 移除时间范围、token 汇总、费用统计及历史补算表单，提供“查看模型统计”链接。
- 切换记录默认折叠，继续保留切换理由和审计；SelectBench 保留现有独立入口，配置页移除运行列表，只留跳转链接。
- 首轮处理进度和预算恢复状态放到统计页顶部，仅在进行中或异常时展开；结束的历史状态折叠。
- 定价与参考目录仅在进入价格标签或打开对应编辑界面时查询，不能把所有内容隐藏后仍在首次加载时全部请求。

价格仍属于配置，但与连接和能力分配分开操作，避免配置页继续形成一条长页面。

### 3.2 模型统计：新增 `/admin/model-stats`

后台导航新增“模型统计”，与“大模型配置”并列。统计页默认打开“调用与用量”，另设“费用”标签。

```text
模型统计                         [返回大模型配置]
时间：最近 24 小时 / 7 天 / 30 天 / 自定义（北京时间）
筛选：模型、能力                   [更多筛选]

[调用与用量] [费用]

调用与用量：
  总请求、成功率、已知输入/输出 token、缓存率与覆盖情况
  模型汇总表（默认一个型号一行）
  点击某模型 → 查看连接、用途或单次请求

费用：
  API 费用、订阅 API 等价金额（分别按币种展示）
  可计算费用覆盖率、部分金额请求数、费用未知请求数
  连接/型号汇总表
  费用未知项摘要（默认折叠）
  [历史费用补算]（按需打开高级区域）
```

使用一套明确的时间范围，调用和费用统计都按 attempt 的 `started_at`、开始包含/结束不包含查询。自定义日期按北京时间换算，结束日包含整天；一次页面请求固定同一个截止时间，避免两个标签使用略有差异的窗口。

模型筛选适用于两个标签；能力映射到对应的用途集合。连接、具体用途、计费类别、币种和费用状态放入更多筛选，其中费用专用筛选仅影响费用标签并明确标识。切换筛选后重置相关分页，URL 保留标签及筛选，支持刷新、分享和返回。

## 4. 调用统计：按模型合并

### 4.1 默认分组规则

默认按历史请求的型号聚合，使用 `coalesce(a.requested_model, a.model)` 作为型号标识；两者都缺失时归入“型号未知”。不使用当前默认连接反推历史型号，也不通过名字相似自动合并不同型号或别名。

| 维度 | 默认处理 |
| --- | --- |
| 请求型号 | 默认唯一分组维度 |
| 能力、用途 | 作为筛选或下钻维度；未筛选时合并同型号的所有用途 |
| 连接 | 默认合并同名请求型号的调用与 token，可下钻查看来源；多连接时标注“多个连接” |
| 提示词版本 | 不显示、不参与普通统计分组 |
| 计费类别、实际/估算币种、价格快照 | 不参与调用统计分组，费用移到费用标签 |
| 耗时、成功率、token、缓存率、用量完整性 | 全部是指标或覆盖信息，不参与分组 |

例如截图中的 `gpt-6-luna`，即使有不同提示版本、部分请求无缓存数据、部分请求无定价，默认也只显示一条模型汇总。筛选“事件归组”时，`group_article`、`group_signal`、`group_story` 合并到该型号一行；只有主动查看“按用途明细”时才拆分。

调用与 token 允许跨连接观察同名型号的合计表现；费用归属仍保留稳定连接 ID。需要比较不同渠道表现时，进入该模型的连接明细即可。

### 4.2 聚合计算口径

直接对筛选范围内的原始 `receipt_attempts` 聚合，不在浏览器中合并已经分页或已经算完分位数的旧统计行。

| 指标 | 计算方式 | 缺失处理 |
| --- | --- | --- |
| 调用次数 | 真实 attempt 数；重试各计一次，复用回执不新增次数 | 缺少用量仍计调用 |
| 成功率 | `received 次数 / 总调用次数`，沿用现有请求状态语义；失败、结果未知、在途分别计数 | 零调用显示“—”；结果未知不算成功 |
| 耗时 p50 / p95 | 对合并后原始有效耗时样本重新计算分位数 | 无样本显示“未知”，缺失耗时不补 0；在途无完整耗时不参与 |
| 输入、输出 token | 各自累加有效且已报告的数值 | 全部缺失显示“未知”；部分缺失显示“已知合计 + 覆盖说明” |
| 缓存读取 token | 累加明确报告的缓存读取数 | 全部缺失显示“未知”，明确报告 0 才显示 0 |
| 缓存率 | `有效缓存读取 token 合计 / 同批已报告缓存读取明细的输入 token 合计` | 分母为 0 或无有效样本显示“未知”；缺明细请求不当作未命中 |
| 推理 token | 累加已报告值，作为输出 token 的子集展示 | 不再加到输出总数；缺失保持未知 |

成功率和缓存率不能直接平均旧行百分比；p50/p95 不能相加，也不能按调用量加权平均。API 返回用于重算的计数、分母和覆盖字段，前端负责格式化。

缓存率继续表达“缓存读取命中比例”。“输入减缓存读取”若继续展示，应标为“非缓存读取输入”；不能在缓存写入未知时称作精确的普通输入，也不能把缺缓存明细的请求全部归入非缓存。缓存读/写完整性与缓存读取命中率的覆盖情况分别保留。

示例：三次请求输入为 100、900、500，前两次报告缓存读取 80、90，第三次缺缓存数据。合并后输入 1500，缓存读取 170，缓存率为 `170 / 1000 = 17%`，缓存读取明细覆盖 `2/3` 次，另有 500 输入 token 的缓存状态未知。不能平均为 45%，也不能用全部 1500 作为分母。

### 4.3 表格展示

默认列：模型、调用次数、成功率、耗时 p50/p95、输入/输出 token、缓存率。缓存 token、推理 token、覆盖率和失败/未知/在途计数放在行展开详情中；部分覆盖时，在对应值旁显示简短“部分”标记。

使用“未知”表示没有可用数据，使用“—”表示无适用计算结果，例如范围内零调用。部分数据缺失不导致整行消失，也不把已知合计冒充完整总量。`tokensIn`、`tokensOut` 等契约需支持全缺失的 `null`，并提供每项的已报告/缺失请求数，避免沿用当前 `null → 0` 的转换。

请求数据只统计模型调用的 live attempts，排除 imported/replay；保留历史缺归属项。不将 SelectBench 或其他非模型请求混入，能力映射以外的模型用途进入“其他用途”，全局统计每个 attempt 只计一次。

## 5. 费用统计：汇总优先，未知项按需展开

### 5.1 默认汇总层级

费用主表默认一条“连接 + 请求型号”一行，不按用途、提示版本、价格版本或费用状态拆行。行内分别展示各个计费类别、币种的金额；只有查看用途明细时才按用途细分。

金额计算分两层：

1. 每个 attempt 先选择唯一有效费用：实际费用优先，否则采用完整或近似估算；部分金额单列，未知无可加金额。有效币种取该笔有效金额的币种，不再同时以实际币种、估算币种的空值组合拆组。
2. 费用分别按 `连接 ID + 请求型号 + 计费类别 + 有效币种` 求和，再挂到同一条连接/型号主行。行的请求数和覆盖数从独立 attempt 集合计算，不能因一行含多个金额分项而重复计数。

例如同一连接的一个型号既有旧 USD 记录又有新 CNY 记录，主表仍是一行，金额单元格分别列 USD 与 CNY。API 与订阅 API 等价金额同样分列，绝不相加。连接重命名或删除不改变历史归属；连接缺失仍标记“历史未归属”。

### 5.2 大量未知费用的处理

- 顶部始终显示完整筛选范围的请求数、可计算费用覆盖率、部分金额数和费用未知数。近似估算是可计算费用的子集，不能重复累计到覆盖请求数。
- 主表优先展示存在实际金额、完整/近似估算或已知部分金额的连接/型号组合。明确记录的零费用也正常展示，不能使用 `金额 > 0` 判断是否有费用数据。
- 同一组合同时有已知与未知费用时，仍只有一行，显示已知金额及“另有 N 次费用未知”。已知金额不是该范围的完整账单。
- 完全无金额的组合默认不逐条铺开，收为“费用未知 N 次，涉及 M 个连接/型号”的折叠摘要。选择展开或点击原因后再查询并分页，仍可按型号、连接、用途追查。
- 主表默认每页 10 行，可选 20/50 行。排序按请求数或同币种金额，不对 USD/CNY 混合金额排序；按金额排序时需先选择币种和计费类别。纯未知列表独立分页，不抢占有金额列表的前几页。
- 全部费用未知时，展示“当前范围费用未知”及原因摘要，不展示空金额卡片阵列，也不显示总费用为 0。

“隐藏纯未知行”只是展示模式，不改变顶部全范围汇总的分母。显式选择费用状态筛选时，顶部明确说明按筛选后的范围统计；翻页和展开不改变总额或覆盖率。

### 5.3 区分未知原因

不再把所有状态都写成“未定价或缺少用量”。根据已保存的估算状态和原因展示：

| 情况 | 展示及可执行操作 |
| --- | --- |
| `unpriced` | “未定价”；有明确归属时可跳转对应连接/型号的价格设置 |
| `missing_usage` | “缺少用量”；查看请求明细，不能靠补价格解决 |
| `invalid_usage` | “用量异常”；查看校验原因，不把非法值加入用量或金额 |
| `partial` | “已知部分金额”；单列已知值及不完整原因，不当作完整费用 |
| 缺少连接归属 | 单独标记“历史未归属”，不自动归给当前连接 |
| 缺少历史状态或原因 | “历史费用信息不足”，不猜测具体原因 |

费用状态主分类互斥统计；“历史未归属”和“缓存明细不完整”作为额外覆盖标签，可能与费用主分类重叠，不能相加得出未知总数。一条请求有多个原因时保留详情，但原因摘要不能把同一请求重复当成多次费用未知。

### 5.4 历史补算保留为高级操作

历史补算从配置页移到统计页费用标签的“历史费用补算”入口，打开时才加载运行列表、预览表单和选定运行结果。默认展示实时请求费用，补算结果仍独立选择某一轮查看，不与原始金额、其他轮次相加。

调价只能影响后续请求；合并统计和折叠未知项不会补齐已经缺失的价格快照、用量或连接证据。补价格后不自动把旧记录变成已定价，不为追求覆盖率重发模型请求。补算开关、只读预览、证据映射、独立结果表及继续执行机制继续保留。

## 6. 前后端改造范围

### 6.1 查询职责拆分

| 入口 | 职责 |
| --- | --- |
| `/api/admin/model-config` | 沿用现有连接和账号配置查询 |
| 新增 `/api/admin/model-capabilities` | 能力当前分配、模型选项及切换记录，不执行用量和费用聚合 |
| 新增 `/api/admin/model-stats` | 按模型聚合调用、耗时和 token，支持统一时间与筛选；按需查连接/用途明细 |
| `/api/admin/model-pricing`、`/api/admin/model-price-catalog` | 沿用现有价格管理，仅配置页价格标签按需查询 |
| `/api/admin/model-costs` | 改为连接/型号主行及分类币种金额分项；返回未知摘要和历史连接筛选选项；请求明细按需查询 |
| `/api/admin/model-cost-backfills*` | 沿用补算流程，仅打开高级区域时调用 |

现有 `POST /api/admin/models/:capability` 切换接口保持行为。旧 `GET /api/admin/models` 暂保留兼容读取，内部复用拆分后的查询，避免现有只读维护脚本立即失效；新页面不再依赖它加载整套配置和统计。

筛选选项需覆盖历史连接和已删除连接，不能为获取连接名称而加载整套价格编辑数据。配置与统计 loader 真正分离；费用明细和补算区域展开后再请求，不能只使用 `<details>` 隐藏已经查出的数据。

## 7. 实施顺序

1. **拆分读取职责和契约**：固定统计范围与合并口径，提供轻量能力配置查询、独立模型统计查询及费用新结构，保留旧读取兼容。
2. **精简配置页并新增统计页**：完成导航、标签、能力分配列表及独立 loader，把价格操作放入配置标签。
3. **落地调用统计合并**：移除提示词版本和费用维度分组；实现缺失值与覆盖信息、模型到连接/用途的下钻。
4. **压缩费用列表**：连接/型号主行、币种和类别分项、纯未知摘要、独立分页、按需明细及补算入口。
5. **隔离验收并更新文档**：检查聚合前后计数与金额守恒、筛选兼容、查询负载和页面操作；准备发布说明。

## 8. 验收标准

| 场景 | 预期结果 |
| --- | --- |
| 进入大模型配置 | 默认只看到连接和能力分配；不请求调用统计、费用、补算或未打开的价格目录 |
| 进入模型统计默认标签 | 读取调用与用量，不预加载价格编辑、费用明细或补算运行 |
| 截图中的同型号、多提示版本、多用途、缓存缺失和定价差异 | 默认合并成一条模型行；筛选事件归组后仍是一条；普通统计没有提示版本列 |
| 同名型号来自多个连接 | 调用默认合计，可查看连接差异；费用主行按连接归属，不丢历史连接 |
| 多行成功率和耗时合并 | 成功率用次数重算，p50/p95 从原始样本重算；与直接查询原始 attempts 一致 |
| 有缓存、零缓存、无缓存明细混合 | 读取缓存率按有效输入加权，缺失不算未命中；覆盖数和未知量可追查 |
| token 全缺失或部分缺失 | 分别显示“未知”或“已知合计 + 部分覆盖”；不展示虚假的 0 |
| 一个回执被复用或存在多次真实重试 | 复用不多计，真实 attempt 各计一次；下钻前后总数和 token 一致 |
| 同连接/型号混合实际、估算、部分、未知 | 主表一行；实际费用优先一次，部分金额单列，未知计数仍可见 |
| 同型号存在 USD/CNY、API/订阅等价 | 调用统计不拆行；费用按类别与币种分项展示，不换汇、不跨类别求和 |
| 大量纯未知费用或全部费用未知 | 默认只有摘要，不逐用途铺满；可展开分页；不把未知显示成免费 |
| 明确零价格、零实际费用、小额费用 | 零正常保留，小额保留适当精度或可查看精确值，不误判为未知 |
| 翻页、折叠、切换时间或筛选 | 翻页/折叠不改变全范围总数；筛选后页码复位，北京时间边界一致 |
| 调价、历史补算和旧链接 | 不改变旧快照及原始费用；补算单轮隔离；旧统计链接可到达新入口 |

实现时使用本地模型替身、合成费用记录和隔离测试库，保持测试安全阀关闭，不访问生产库、真实模型或外部付费服务。按 [隔离测试说明](testing.md) 和 `AGENTS.md` 完成类型检查、相关聚合回归、完整后端测试、网页构建与网页测试，站点启动后执行冒烟，并如实记录结果。本文档阶段只检查方案与代码依据、文件内容及差异格式。
