## 3. 安全边界修复

### S1：受限主机名的尾点归一化

优先级：高。参考 `ea96060`。

当前位置：[URL 防护](../packages/backend/src/lib/url.ts)中的 `blockedHostname()`、`assertPublicUrl()` 和 `guardedLookup()`。

现有名称黑名单匹配 `localhost`、`.localhost`、`.internal` 等，但没有先去掉 DNS 根域尾点。`localhost.`、`child.localhost.`、`metadata.google.internal.` 和 `anything.internal.` 因此无法命中名称规则。

本轮用本地替身将 DNS 回答固定为公开 IP，在不发出网络请求的情况下复现：无尾点 `localhost` 被拒绝，四个带尾点名称在 URL 检查和连接查找两个入口均被接受。**这只证明名称规则缺口**；现有 IP 地址检查仍会阻止实际解析到内网的地址，不能据此宣称已经实现完整 SSRF 利用。

实施方案：

1. 在共享名称判断中先统一小写及根域尾点，再匹配受限名称，使两个入口使用相同规则。
2. 保持普通公网域名的尾点写法可用，不改写文章保存地址、URL 判重身份或页面原文链接。
3. 保留本站 `assertPublicUrl(url, allowPrivate, proxied)` 参数及代理语义。本站对代理代解析域名使用较窄的内网地址判断，不能被上游不同签名或解析替身参数覆盖。
4. 保留连接时的二次地址检查及调试开关的原有权限边界。

验收：四个名称及其大小写组合均在 DNS 查询之前拒绝；普通 `example.org.` 可通过受控公开解析；IP 字面量、混合 DNS 回答、IPv6 内嵌地址、DNS 重绑定及代理分支既有行为不退化。测试采用本地解析替身，不查询真实域名。扩展现有 [URL 测试](../tests/url.test.ts)，按本站接口适配上游用例。

### S2：内联图片地址的 MIME 校验

优先级：高。参考 `ea96060`。

涉及：[图片判断](../packages/backend/src/lib/image-url.ts)、[正文清洗](../packages/backend/src/content/sanitize.ts)、[图片输出](../packages/backend/src/media/imgproxy.ts)。

本站辅助函数名为 `isTrackingImage()`，上游已改为 `isNonArticleImage()`。现有清洗允许 `<img>` 的 `data:` scheme，输出代理又直接返回以 `data:` 开头的地址；仅有跟踪域名与一像素图过滤，未校验内联 MIME。

只读运行确认以下值均被清洗和输出路径保留：`data:text/html,probe`、`data:application/javascript,probe`、`data:,probe`、`data:image/png`。最后一个没有数据分隔符，也不应视为有效图片。此结论是非图片地址未被过滤，不代表浏览器一定执行其中内容。

实施方案：

1. 在采集清洗和公开输出共用的判断中校验 `data:`。仅对具有 `image/` MIME 且有合法数据分隔符的形式放行，大小写处理一致；保留现有跟踪域名、小尺寸过滤及正常 HTTP(S) 图片。
2. 统一 `src`、`data-src`、`data-original` 的解析后过滤，公开读取也过滤旧数据库中已保存的非图片地址。
3. 对被拒绝的正文图片移除整个标签，保留前后文字，避免空图及失效属性残留；对封面／海报等消费者明确返回空值的行为。
4. 不改图片签名格式、签名有效期、响应式尺寸、全文许可和缓存策略，不为了清理旧内容批量抓取或调用模型。
5. 上游仍允许 `image/svg+xml` 等图片 MIME；本轮不借此宣称 SVG 内容已得到独立安全验证，也不扩大现有允许范围。

验收：上述四种非法值在清洗、单图输出和正文图片输出中被拒绝；PNG、JPEG、既有 SVG 图片及普通 HTTP(S) 图片按原许可保留；三种来源属性一致；清洗幂等；跟踪图和 1×1 图继续过滤；正文、RSS 和文章阅读回归。以现有 [正文测试](../tests/markdown-body.test.ts)及媒体相关用例为基础补充实际行为测试，不只检查源代码字符串。

### S3：摘要与翻译模板的共享安全规则

优先级：高。参考 `ea96060`。

五个目标文件位于 `industry/prompts/`：`summarize-article.md`、`summarize-long-post.md`、`summarize-short-post.md`、`translate-body.md`、`translate-post.md`。共享规则已存在于 [safety.md](../industry/prompts/safety.md)，将标题、正文、引用和图片文字视为不可信材料。

本轮实际展开这五个模板，均未包含这段共享规则；其他防幻觉规则不能替代“不得执行材料中指令”的要求。

实施方案：在各模板任务说明附近引用 `{{> safety}}`，保留本站已有的结论优先、标题自洽、行业规则、事实约束、时间锚点、HTML 链接占位和 JSON 输出契约。不用上游整份行业模板覆盖本站文件。

[提示词加载器](../packages/backend/src/editorial/prompts.ts)会将引用内容纳入版本哈希。实施时需要检查版本变化对在途及重试任务的影响：不得因新的 prompt hash 让未知旧回执绕过等待，也不主动重评或批量重翻历史内容。若现有任务边界无法保证这一点，先补充兼容方案，再推进实现。

验收：实际展开五个模板可见共享规则且无未解析引用；原有变量完整、输出格式和翻译占位约束保持；内容哈希能反映修改；本地模型替身验证材料中的恶意指令不会改变系统任务的构造及输出处理；已有响应复用、未知回执等待和关闭安全阀的行为保持。测试只能验证应用构造与处理，不把本地替身结果写成真实模型抗提示注入效果评测。

### D1：暂缓 Caddy 响应头改动

上游同时新增 HSTS、`X-Frame-Options`、`X-Content-Type-Options`、`Referrer-Policy` 和 `Permissions-Policy`。本站当前使用已确定的 HTTP 私网入口，单改 [Caddyfile](../deploy/Caddyfile)不能证明实际请求经过 Caddy。

本轮暂缓整个 Caddy 配置部分，不要求将本站迁为 HTTPS。后续如需统一响应头，应先确认实际入口及已有响应头，再按 HTTP／HTTPS 语义分别设计和验证；这项暂缓不阻挡 S1—S3。

## 4. G1：预算等待后的归组恢复

优先级：高。参考 `791a6f5`；需要独立适配，不能直接套补丁。

### 4.1 当前路径与风险

- [归组逻辑](../packages/backend/src/events/group.ts)在候选判定的通用异常分支调用 `markGrouped()` 和 `publishArticle()` 后重新抛出异常；预算不足也会进入此分支，造成“尚未完成归组，但已写入 grouped_at”。
- [事件任务](../packages/backend/src/jobs/events.ts)没有单独处理预算等待。[归组队列](../packages/backend/src/jobs/queue.ts)采用 `retryLimit=4`、20 秒初始延迟及退避；预算窗口可能长于这段重试周期。
- `retryReleasedReceiptJobs()` 依赖失败任务的 `receiptId` 和后续放行审计；预算检查在请求发出前失败时通常没有可放行回执，不能依赖这一机制恢复。
- [内容补扫](../packages/backend/src/jobs/content.ts)只查 `processing_state='new'` 的文章，不是归组补扫。文章已分析完成时，不能保证预算恢复后自动接续归组。

这是代码路径检查得到的恢复缺口。本轮没有查询生产数据库或任务队列，不声明当前存在多少篇受影响内容，也不批量重排历史任务。

### 4.2 与上游的结构差异

上游补丁将 `BudgetExceededError` 对应的 `grouping_status` 保持为 `pending`，由已有 `sweepUngrouped()` 续接。本站没有这些字段或补扫入口，只有 `grouped_at`、`regroup_pending` 和现有 pg-boss 任务。只复制三行条件无法构成完整修复。

### 4.3 实施方案与设计闸口

推荐先评估在现有队列内形成明确的“等待后重排”闭环：预算异常在事件任务边界单独处理，遵守 `retryAfterSeconds`；等待不能消耗真正失败的有限重试，也不能改写为完成。实现前必须验证同一 `singletonKey` 的活跃任务能否可靠安排下一次，以及事务、进程退出和重复入队时的行为。

不以增加 `retryLimit`、固定无限重试或直接修改 pg-boss 内部状态替代持久恢复。恢复任务必须能经受 worker 重启；如现有队列无法保证“记录等待与下一次任务”原子持久化，再设计最小的增量等待状态和补扫，而非搬入上游整套状态机。

设计确定前必须解决：

1. 预算、在途、配置缺失、未知结果、正常停止及真实失败如何分类；可复用本站 `requestWait()`，但不能把未知结果当作可自动重发。
2. 当前 revision、人工归属、来源隔离／撤回、合并目标变化如何在恢复前重新核对；不得覆盖等待期间的人工决定。
3. 公开可见性与归组完成如何分别表达。现有 `grouped_at` 参与精选可见时间计算，不能简单清空后导致文章长期消失或改写时间轴。
4. 候选变化或部分模型已返回时，如何保留稳定请求身份及已保存结果；不得用重评或新轮次绕过未知回执。
5. 下一次入队与当前任务结束之间发生崩溃时，谁负责继续；重复恢复如何去重；真实失败如何仍然有界并可诊断。
6. 若必须增加数据库状态，单独写明兼容旧应用的增量迁移、索引、锁和回退行为；部署仍遵守[手动部署](manual-deploy.md)。上游本轮没有新迁移，不代表本站适配必然不需要迁移。

### 4.4 验收

| 场景 | 必须满足 |
| --- | --- |
| 分钟、小时、日预算或手动停用预算 | 不发出模型请求，不伪装完成，保留待恢复任务；不提高限额 |
| 预算恢复 | 自动接续原文章／原处理身份；任务不重复排队，完成后不反复补扫 |
| 等待时间超过四次队列重试周期 | 仍可恢复，不永久遗落 |
| 在途或未知回执 | 继续沿用原等待／放行保护；没有额外付费尝试 |
| 模型已响应、业务事务失败 | 复用响应，归组业务与回执完成一起提交或回滚 |
| 等待期间人工纠正、文章修订或许可撤回 | 重新核对输入及权限；不写回旧归属或旧公开文字 |
| worker 在等待、重排或提交边界退出 | 重启后可恢复，任务不会丢失或并发归组 |
| 真实错误 | 继续有界失败并保留诊断，不被无限等待掩盖 |
| 公开页面与时间轴 | 不靠错误的完成标记维持公开，也不因修复重置收录时间 |

扩展 [归组恢复测试](../tests/events-oss-recovery.test.ts)和回执相关回归，使用本地模型替身及隔离空库。补充真正执行队列重排／恢复的行为验证，不能只验证异常类型或数据库某个状态值。

## 5. E1：SelectBench 输入与跨模型证据校验

优先级：中。将 `3c69b49` 和后续 `e57da5a` 作为同一项适配，避免只完成输入校验而遗漏比较一致性。

涉及：[评测 CLI](../scripts/eval-selection.ts)、[报告导入与读取](../packages/backend/src/admin/selectbench.ts)、[管理员路由](../apps/api/src/routes/admin.ts)、[校准文档](selection.md)。

### 5.1 本站缺口

CLI 当前只逐行 `JSON.parse`，没有在采样及模型调用前验证整个标注集；重复 ID、非法答案、材料结构错误及空 split 可能进入后续流程。导入端没有上游新增的证据预校验，`ON CONFLICT DO NOTHING` 还可能静默吞掉同模型的重复案例。

比较读取按 `case_id` 聚合并取 `min(gold)`，单模型结果过滤又按各条记录自己的 gold 计算；若不同模型对同一案例携带不同人工答案，并排显示与误判筛选就可能使用不同基准。

本站没有上游的 `scripts/eval-selection-core.ts`、`scripts/eval-tools.ts` 等新拆分结构；同时导入函数仍兼容按模型名直接作为顶层 key 的旧报告格式。移植时保留这些现有兼容语义，不整体替换 CLI 或导入函数。

### 5.2 输入校验

在模型选择、数据库操作和任何模型请求之前解析并验证完整 JSONL，然后才执行 split 筛选及采样：

- 保留空行、`//` 注释和 CRLF 支持；错误报告原文件的物理行号。
- `caseId` 非空且整个标注集不重复；`gold.decision` 仅允许 `select`、`reject`、`either`。
- 校验 `material`、`sourceFacts`、`gold` 对象及必要文本字段；可空字段保留空值语义；日期和布尔值合法；可选 sampling 信息不被丢弃。
- 所选 split 没有案例时给出明确错误，不输出看似成功的零样本评测。
- 只增加本项所需的纯解析／校验模块，不顺带移植模型选择、评分策略、并发或预算策略。

### 5.3 导入与跨模型一致性

在任何 run、case 或审计写入之前完整校验本次报告的所有模型证据：

1. `cases` 省略时继续允许摘要报告；存在时必须为数组。
2. 每模型内部的案例 ID 非空且不重复，gold 值合法。跨模型重复案例 ID 是正常比较需求，不能一律拒绝。
3. 同一案例在不同模型下的 gold 必须相同；模型自身 `decision` 可以不同，各模型覆盖的案例集合也可以不同。
4. 所有输入校验失败统一返回明确的 HTTP 400，并指出模型和案例，保留现有鉴权、CSRF 及长度限制。上游第一批部分分支抛普通 Error，本站会映射为 500，不能原样复制后忽略这个差异。
5. 错误报告不得留下部分运行、结果或审计。合法报告继续遵守既有事务及审计行为，不用修改历史报告掩盖问题。

验收：无效 JSON、物理行号、注释及空行、重复 ID、无效 gold、结构和日期错误、空 split；CLI 在不可用数据库且模型安全阀关闭时先报输入错误；导入失败前后 run／case／audit 计数一致；`reject`／`either` 冲突均为 400；合法模型分歧、部分覆盖、摘要报告和旧报告格式保留；tp/fn 等筛选与并排显示采用同一人工答案。

### 2026-10-15 实施决定

- G1 初版使用本站 pg-boss `short` 策略：它允许一个活跃任务之外保留一个相同 singletonKey 的待执行任务。通过公开 `complete`、`send`／`update` API 与已有事务适配器，将完成和延迟后继一起提交；读取并锁住当前活跃行，不直接改 pg-boss 内部状态，不新增等待表、本站应用迁移或补扫调度。保留原优先级、剩余真实失败重试额度和载荷，若已存在较新后继则保留其载荷并遵守等待时间。事务失败时原任务仍活跃，既有队列恢复负责接续。后续领取轮次保护及依赖内部升级见本节最前的审核续接记录。
- S3/G1 在回执领取事务中核对同一文章输入和用途的其他未知回执；提示词版本变化时也先等待旧在途回执。复用已保存响应仍走原逻辑，不修改 `logicalKeyFor`、请求身份或预算。引用共享安全规则会自然改变提示词哈希，不扫描或重算历史材料。
- E1 只新增纯解析模块，使用本站实际分级 `T1/T1_5/T2/EXCLUDE_MP`。导入与审计同事务；旧格式、摘要报告及合法的跨模型分歧保留。读取历史冲突报告时明确报错，不以 `min(gold)` 掩盖冲突或修改旧数据。
- S2 按图片 MIME 和分隔符判断内联图片，保留现有 SVG MIME 允许行为；本轮没有进行 SVG 内容安全验证，也没有更改图片签名、许可和缓存。
